# 皮肤系统升级开发文档 —— CSS 覆盖通道 + 资产通道 + 配置协议 + 互斥规则

> 交接文档：面向后续开发者（人或 AI）。目标是在**不破坏既有皮肤系统语义**的前提下，把皮肤表现力从「纯数据 token」升级到对齐 dsh-deep-whale 皮肤系列的「CSS 覆盖层 + 资产 + 自声明配置」水平。
> 所有现状描述均来自代码核实（2026-09-23，对应台账 R41–R43），引用处标注了文件与符号名。**动手前先通读第 0 节红线。**

---

## 0. 硬约束红线（违反即返工）

1. **皮肤永远不能注入 `<script>` / JS 事件**。CSS 层是纯样式，资产是图片。这是与 dsh 的本质安全差异，是卖点不是缺陷。
2. **不得改动以下既有语义**（R39–R43 已固化，另有消费方）：
   - `resolveSkinTokens` / `flattenSkinTokens` 的合并与落键规则（`plugins/contributions.ts`）；
   - `useSettings` 的 uiTheme「用户显式操作 > 皮肤默认」裁决（`hooks/useSettings.ts` 的 `uiThemeTouchedRef` 门禁）；
   - `bootstrapSkinEngine` 的「先 load 后 apply」顺序（`plugins/skin-engine.ts`——R43 修过自覆盖 bug，顺序敏感）；
   - `BUILTIN_ICONS` 规范键不可被插件注册遮蔽（`plugins/icon-registry.ts` 的 `registerIcons` 拒收规则）；
   - manifest 校验的「未知字段一律拒绝」原则（`plugins/manifest.ts`）——**扩 schema 必须在 v1 契约内做可选字段**，即所有新字段可选 + 显式类型校验，不改 `MANIFEST_VERSION`。
3. **插件故障隔离语义**：任何新增通道（CSS/资产/配置）解析失败只允许记录（console.error / rejected 列表），不允许抛错打断启动（对齐 `plugins/profile.ts` 的 rejected[] 语义）。
4. **本体不可迁移文件**：`components/MainCanvas.tsx`、编辑态手势热路径、`GalaxyStarLayer(LOD0)`、`ErrorOverlay/Loader`、`CanvasSettings` 壳。CSS 皮肤不得依赖改这些文件。
5. 验证基线不可降级：`tsc --noEmit` 零错误、`npm run check:foundations` ok、`vite build` 通过、无头浏览器 `localStorage['bp-boot-errors']` 为空。

## 3. 设计总览：五层模型

| 层 | 内容 | 状态 |
|---|---|---|
| token 层 | CSS 变量（颜色/圆角/字体/壁纸/图标覆盖），支持混搭 | ✅ 已有，不动 |
| **CSS 层** | 皮肤自带作用域样式表，整层注入/移除 | 🆕 M1 |
| **资产层** | 皮肤自带图片（立绘/装饰/预览图），构建期内嵌 dataURI | 🆕 M1 |
| **配置层** | 皮肤自声明设置项，管理面板渲染，按 skinId 持久化 | 🆕 M2 |
| **管理层** | 互斥规则、预览/标签/排序元数据、管理面板展示 | 🆕 M3（元数据提前到 M1） |

**核心作用域约定**（对齐 dsh，名称换我们的）：

- CSS 皮肤激活时，引擎在 `document.documentElement` 写属性 `data-bp-skin-active="<skin-id>"`；
- 皮肤 CSS 的**每一条规则都必须以 `[data-bp-skin-active="<skin-id>"]` 开头**（sanitizer 校验，见 4.4）；
- 同一时刻**最多一个 CSS 皮肤激活**（互斥由单一持久化字段天然保证）；token 层（含混搭）独立运行，两者叠加时 CSS 层的结构/装饰与 token 层的颜色变量互补。

## 4. M1：CSS 覆盖通道 + 资产通道

### 4.1 API 设计（`plugins/skin-engine.ts` 内新增）

```ts
// —— CSS 层注册表（模式对齐 icon-registry 的 registerIcons）——

/** 注册皮肤 CSS（纯文本）。返回 disposer；ownerId 重复注册覆盖旧值。 */
registerSkinCss(ownerId: string, skinId: string, cssText: string): () => void;

/** 激活 CSS 皮肤：写 data-bp-skin-active 属性 + 挂 <style>；传 null 关闭。落盘。 */
setCssSkin(skinId: string | null): void;

/** 当前激活的 CSS 皮肤 id；无则 null。 */
getCssSkin(): string | null;
```

实现要点：

1. `<style>` 元素：`id = "bp-skin-css-<skinId>"`，挂在 `document.head`，带 `data-bp-skin-css="<skinId>"` 属性；切换时旧元素先移除（单元素互斥，绝不并存两个激活皮肤）。
2. 注册与激活分离：插件 activate 时注册 CSS 文本（disposer 随插件卸载自动移除 `<style>` + 若正激活则回落 `setCssSkin(null)`）；用户在主题库点选才激活。
3. **激活的 CSS 皮肤被卸载时**（插件 disabled/移除）：`setCssSkin(null)` 回落，并 console.error 记录——不允许留下无主的 style 元素。
4. 持久化：`bp-skin-state` 扩展为 `{ skinId, composite, cssSkinId: string | null }`。`loadSkinState` 对缺失的 `cssSkinId` 字段容错（旧数据视作 null）。bootstrap 恢复分支加：`cssSkinId` 存在且该皮肤已注册 CSS 才激活，否则忽略（隔离语义，不得抛错）。
5. `registerSkinCss` 时做 sanitizer（见 4.4），不合格 CSS **整份拒收**并 console.error，不部分应用。

### 4.2 manifest 扩展（`plugins/manifest.ts`，全部可选字段）

```ts
interface SkinManifestEntry {
  id: string;
  name: string;
  mode?: 'dark' | 'light';
  tokens?: SkinTokens;
  // —— v1 兼容扩展 ——
  /** 亮/暗预览图（构建期经 vite 资产导入转 dataURI 或 URL）。 */
  preview?: { dark?: string; light?: string };
  /** 标签（主题库筛选展示）。 */
  tags?: string[];
  /** 主题库排序权重，小者在前；缺省 100。 */
  order?: number;
}
```

校验规则：`preview.*`、`tags` 必须是 string（tags 为 string[]，≤8 项，每项 ≤16 字符）；`order` 为 number。不合法 → 该皮肤进 rejected 隔离（沿用现有 profile 语义），**不要抛错**。

### 4.3 插件侧用法（文档内示例，供开发者照抄）

皮肤插件目录结构（以新增示范皮肤 `builtin/skins-aurora` 为例）：

```
builtin/skins-aurora/
├── manifest.json      # contributes.skins[0] 含 preview/tags/order
├── index.ts           # activate：registerSkinCss + 返回 disposer
├── skin.css           # 全部规则以 [data-bp-skin-active="builtin.skin-aurora"] 开头
└── assets/
    └── glow.png       # 构建期转 dataURI
```

```ts

import skinCss from './skin.css?raw';
import glowUrl from './assets/glow.png';          // vite 自动转 dataURI/URL
import { definePlugin } from '../../plugins/define-plugin';

export const skinsAuroraPlugin = definePlugin({
  manifest,
  activate(ctx) {
    const engine = /* kernel.use(SKIN_ENGINE_SERVICE) 方式获取，见 ui-skin-picker 的用法 */;
    return engine.registerSkinCss('builtin.skins-aurora', 'builtin.skin-aurora', skinCss);

```

并在 `builtin/index.ts` 的 `BUILTIN_PLUGINS` 数组追加一行（现有登记仪式不变）。

> ⚠️ 皮肤插件需要 token 补丁时照旧写在 manifest 的 `contributes.skins[].tokens`（如 aurora 的 accent 色）——**token 与 CSS 同插件两通道，激活整装皮肤时同时生效**。

### 4.4 CSS sanitizer（必须实现，独立文件 `plugins/skin-css-sanitize.ts`）

逐条规则（命中即**整份拒收**并返回错误列表）：

1. 禁止 `@import`、`@charset`（外链注入面）。
2. 禁止 `url()` 包含 `http://` / `https://` / `//`（只允许 `data:` 与构建期相对路径已转成的 URL）；禁止 `javascript:` 任何形式出现（含大小写混淆，sanitize 前先 `replace(/\s+/g,'')` 归一化再检测）。
3. 禁止 `expression(`（古董 IE 向量，防呆）。
4. **作用域校验**：每条顶层规则（`@media`/`@supports`/`@layer` 内层也算）的选择器必须包含 `[data-bp-skin-active="<skinId>"]` 前缀。`@keyframes`/`@font-face`/`@property` 豁免（前三者无选择器；`@property` 只注册自定义属性描述符，其 body 里的 `syntax`/`inherits`/`initial-value` 不是规则）。`@layer` 块形式**递归校验内层作用域**（防它成为后门），语句形式（`@layer a, b;`）只声明层序、无 body，自动放过。其余 `@`-rule 一律拒收。校验方式建议：按顶层块切分后正则检查，不做完整 CSS AST（保持零依赖）。
5. 大小上限：单皮肤 CSS ≤ 512 KB（超限拒收）。

### 4.5 M1 验收标准

- [ ] `builtin/skins-aurora` 示范皮肤：激活后（无头浏览器）`document.documentElement` 有 `data-bp-skin-active="builtin.skin-aurora"`，head 中有对应 `<style>`，视觉变化可见（截图）；
- [ ] 切到其他 CSS 皮肤：旧 `<style>` 移除、属性更新（同一时刻至多一个）；

## 5. M2：皮肤配置协议（对齐 dsh 的 exposeSkinCustomization）

### 5.1 Schema（`plugins/contributions.ts` 或独立 `plugins/skin-customization.ts`）

```ts
export type SkinSettingField =
  | { key: string; type: 'boolean'; label: string; defaultValue: boolean }
  | { key: string; type: 'number';  label: string; defaultValue: number; min?: number; max?: number; step?: number }
  | { key: string; type: 'string';  label: string; defaultValue: string; maxLength?: number }
  | { key: string; type: 'select';  label: string; defaultValue: string; options: { value: string; label: string }[] };

export interface SkinCustomizationDecl {
  title: string;
  settings: SkinSettingField[];   // ≤ 12 项
  /** P0-2：config 键 → CSS 自定义属性名；引擎激活/变更时自动投影，皮肤零代码暴露旋钮。 */
  binding?: Record<string, string>;
  /** M4：boolean config 键 → documentElement 属性；属性选择器型开关零代码落地。≤ 8 项。 */
  attributeBindings?: { name: string; key: string; on: string; off?: string }[];
  /** M5：boolean config 键 → documentElement class；class 型组合态开关零代码落地。≤ 8 项，class 名全局不可重复。 */
  classBindings?: { key: string; on: string; off?: string }[];
}
```

### 5.2 机制

1. **声明**：插件在 manifest `contributes.skins[].customization?: SkinCustomizationDecl`（进 manifest 校验：key 唯一、`^[a-zA-Z][a-zA-Z0-9_]{0,31}$`）。
2. **存储**：`localStorage['bp-skin-config.<skinId>']` = `{ [key]: value }`（JSON，try/catch 隔离）。校验：值类型必须匹配 schema，不匹配回落 defaultValue（读取时逐键校验，坏键丢弃）。**不复用 plugin configSchema 通道**（那个绑定插件启停 profile，语义不同；但实现时参考 `validateConfigPatch` 的校验写法）。
3. **订阅**：SkinEngine 增加

```ts
getSkinConfig(skinId: string): Record<string, unknown>;
setSkinConfig(skinId: string, patch: Record<string, unknown>): void;  // 合并 + 落盘 + emit
onSkinConfig(skinId: string, cb: (cfg: Record<string, unknown>) => void): () => void;
```

   事件用 kernel `emit('skin:config-changed', { skinId, config })`；皮肤在 activate 里 `onSkinConfig` 并在 apply 回调里操作自己的 DOM/属性（**皮肤自己持有并清理自己的 DOM**，对齐 dsh 的所有权规则）。
4. **UI**：`ui-skin-picker` 的皮肤卡片展开区渲染 schema 表单（boolean→checkbox、number→number input、string→text、select→select），改动即调 `setSkinConfig`。CSS 皮肤用 `data-bp-skin-setting-*` 属性投影是皮肤自己的事（示例：aurora 用 boolean「显示辉光」控制 `data-bp-skin-active` 的值切换变体），**管理面板不理解皮肤内部选择器**。
5. **声明式投影（P0-2 / M4 / M5）**：引擎在皮肤激活与配置变更时自动投影三种绑定——`binding` 写 CSS 自定义属性、`attributeBindings` 写 HTML 属性、`classBindings` 写 documentElement class（true→`on`；false→`off` 值，未声明 `off` 则移除/不加；切皮肤/卸载时按追踪清单整体清理，不跨皮肤残留）。**M4 起属性型开关不再需要任何内置运行时底座**：原 `builtin.skins-ambient`「皮肤环境层」插件已删除——aurora 辉光（`data-bp-aurora-glow` + `--bp-aurora-glow-opacity`）、abyssal 壁纸（`data-bp-abyssal-wallpaper`）改由两个清单的 `attributeBindings`/`binding` 声明，装饰气泡改纯 CSS（4 个伪元素背景层 × 4 颗，零 JS 零 DOM，`prefers-reduced-motion` 保留）；`bubbleCount` 设置随 widget 一起退役（纯 CSS 无法逐颗计数，存量配置键按未知键忽略）。**M5 放开 sanitizer 的 `@property` / `@layer`**：`@property` 让自定义变量带 `syntax` 类型（颜色/长度可被 `transition` 平滑插值，此前未注册变量的过渡不生效）；`@layer` 块形式放行但**递归校验内层作用域**（不能成为作用域红线的后门），语句形式（`@layer a, b;`）只声明层序自动放过。三种绑定 + 两类 at-rule 就位后，日常新特效只需改 manifest（css / tokens / settings / bindings），本体零改动；需要真实 DOM/交互的特效才考虑内置插件，且先论证为什么不能是前两者。

### 5.3 M2 验收标准

## 6. M3：互斥规则 + 主题库整合

1. **互斥即单字段**：`cssSkinId` 天然单值，无需 dsh 那套两 patch 层原子写（我们没有 YAML patch 层问题）；但要做**启动兜底**：bootstrap 时 `cssSkinId` 指向的皮肤未注册 CSS → 置 null 并 console.warn（对应 dsh issue #65 的坑，我们用隔离语义规避）。
2. **主题库 UI**（`builtin/ui-skin-picker`）：
   - CSS 皮肤卡片带「样式皮肤」徽标 + preview 图（manifest 的 preview 字段，亮暗按当前 mode 选）；
   - 点击行为：token 皮肤走 `setSkin`，带 CSS 层的皮肤走 `setCssSkin`（若该皮肤也有 tokens，两通道同开）；
   - 已有混搭工坊不动；CSS 皮肤卡片上提示「样式层与配色混搭可叠加」。
3. **插件管理面板**：CSS 皮肤插件正常按插件管理（启停走 profile patch），无需新机制。

### M3 验收标准

## 7. 验证与交付约定

1. **每完成一个 M**：`npx tsc --noEmit`（零新错）→ `npm run check:foundations` → `npm run build` → 无头浏览器实测（agent-browser 单命令串联 `open + sleep + eval`，Windows 下跨命令页面状态会丢）→ `docs/实施迭代台账.md` 追加记录（格式参照 R41–R43）。
2. **无头验证钩子**：`index.html` 有常驻启动错误收集（localStorage `bp-boot-errors`）；`window.__bpSkinEngine` 暴露引擎实例；模块可动态 `import(new URL('/plugins/xxx.ts', location.origin).href)` 直测纯函数。
3. **提交粒度**：每个 M 一次完整提交说明，写明改动文件清单与验证结果。
4. 同一文件的多次编辑**必须串行**（并行 Edit 互踩是本项目两次实测翻车点）。

## 8. 风险清单

| 风险 | 缓解 |
|---|---|
| CSS 皮肤破坏布局可用性（dsh issue #65 的「设置按钮消失」） | 作用域强制 + 用户可一键 `setCssSkin(null)`；BOOTSTRAP 保护插件不受任何皮肤影响 |
| 外链 CSS/图片引入隐私与加载问题 | sanitizer 禁外链，资产构建期内嵌 |
| `?raw` 导入的 CSS 打包膨胀 | 512 KB 上限；后续可改按需 fetch |
| 配置键残留 | 按 skinId 命名空间隔离，重装即恢复，不自动清理 |
| 混搭 + CSS 叠加的视觉冲突 | 文档约定：CSS 层管结构/装饰，token 层管颜色变量；示例皮肤遵守示范 |

## 9. 明确不做（本期边界）

- 皮肤 DOM 注入/立绘/MutationObserver——属于普通 UI 插件能力（本架构已支持），不进皮肤契约；
- 第三方插件运行时加载/安装流水线（三期既有规划，另行立项）；
- 皮肤市场/在线分发；
- 在界面上从零自创 token 的可视化主题编辑器（可基于 setComposite 另行立项）。
