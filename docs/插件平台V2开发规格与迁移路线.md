## 0. 接手模型必须先读

目标不是“让插件绕过所有限制”，而是将当前以内置 UI/功能扩展为主的系统，升级为**核心业务能力可组合、受控扩展、必要时可替换的插件平台**。

执行规则：
1. 先重新读取当前源码与已有 ADR/FDD。本文依据审查快照，不保证接手时文件未被其他模型修改。
2. 项目此前检查时不是 Git 工作区。修改前备份本批涉及文件；不得用旧备份覆盖用户新改动。
3. 分阶段实施，不在第一批同时更换内核、重写画布、存储和导入系统。
4. 保留旧插件、项目文档 v2、受限 IPC、操作历史和资源所有权约束。
5. 配置字段声明不代表运行时已实施限制；不得把 manifest 的 host/budget/capabilities 当作已有沙箱证明。
6. 测试先于迁移。不能删除架构断言、放宽安全检查或改写失败用例来冒充通过。
7. 每批报告真实检查结果、体验变化、剩余风险和回滚方式，更新本文实施台账。
8. 文中新增类型/文件是设计草案，必须按现有代码适配；不得声称已经存在。

### 关联文档及优先关系

- `docs/插件系统设计.md`：已有设计，逐项对照，冲突通过新 ADR 明确。
- `docs/插件化迁移清单.md`、现有 ADR/FDD：继承既有边界，不默默推翻。
- `docs/画布交互性能优化实施计划.md`：画布性能约束；插件分发不能进入每个 pointermove 的重路径。
- `docs/资产导入非阻塞管线开发规格.md`：导入状态、取消、预算、分批提交和目标画板规则以该文档为业务依据。
- 本文负责插件平台接口、宿主、授权与迁移；不另造一套与导入规格竞争的队列或资产库。

## 1. 借鉴对象与证据边界

参考项目：DeepSeek Harness。

本次审查树快照：`00102833dfaee1da9f48a3a8eae9d34005a75218`。

固定版本参考：
- [Architecture](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/docs/architecture.md)
- [Capability seams](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/docs/capability-seams.md)
- [Extension cookbook](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/docs/cookbook/extension-cookbook.md)
- [Extensions subsystem](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/docs/subsystems/extensions.md)

### 1.1 应学习的原则

- 核心能力通过服务接口、提供者、消费者连接，而非业务代码直接依赖某个固定实现。
- 核心功能自身也能作为插件组合的一部分。
- 操作扩展点明确区分通知、拦截、包装、结果转换和不可绕过的安全守卫。
- 插件组合、依赖、版本、激活、撤销副作用与部署方式一起设计。
- Host 与 Client 扩展有明确界面；高权限能力与批准机制配套。

### 1.2 不应机械照搬

- Artflow 是有高频交互的媒体画布，不是 Agent 循环。不能给每帧拖动套任意异步插件链。
- 不要求所有核心服务支持运行中热替换。启动期选择提供者已能解决大量扩展需求。
- 不为追求“一切皆插件”开放任意本地文件、进程、数据库和 React 内部状态。
- 不在没有迁移收益验证时直接换 Cordis；框架替换不能代替能力接口设计。
- Harness 文档中的能力不等于 Artflow 已拥有的能力，也不代表所有 Harness 插件无权限约束。

## 2. 当前源码审查结论

| 现有路径 | 已确认现状 | V2 处理方向 |
|---|---|---|
| `plugins/kernel.ts` | 服务容器、贡献注册表、同步事件总线；固定 SLOTS | 保留兼容，补作用域、类型和操作链 |
| `plugins/loader.ts` | builtin 模块激活，收集插件返回的 disposer | 事务式激活与自动归属；先修生命周期再支持外部插件 |
| `plugins/manifest.ts` | 仅 runtime.mode=builtin；Runtime Core 明确不可由普通 patch 替换 | V1 适配器；另立 V2 包与提供者契约 |
| `builtin/index.ts` | 静态导入插件清单，外部加载仍属后续工作 | 引入可验证的包目录/加载器，不再要求第三方改此文件 |
| `plugins/profile.ts` | 已有依赖检查、配置分层与排序 | 复用，增加服务绑定与版本约束，不再造平行 profile |
| `plugins/plugin-profile-manager.ts` | staged 配置，reload 后激活 | 第一版继续保留；后续只对安全贡献支持局部热更新 |
| `plugins/renderer-materialization.ts` | 启动/明确 reload 时生成只读卡片查找表 | 保留低成本查找，通过 revision 原子换表而非 render 中反复扫描 |
| `plugins/card-contributions.ts` | nodeType + React component | 升级完整 NodeTypeDefinition，不仅定义外观 |
| `components/CanvasElement.tsx` | 部分原生类型 switch，插件类型走通用卡片组件 | 渐进迁移，保留旧节点适配器 |
| `hooks/useCanvasInteractions.ts` | 拖动分支仍枚举多种节点类型 | 建立统一几何变换适配层，禁止新类型必须改 switch |
| `plugins/canvas-mutation.ts` | patchElements/getElements | 加入明确目标、校验、事务、结果与订阅的文档服务 |
| `plugins/host-platform.ts` | 平台能力桥、存储/窗口操作；存在 unknown 类型 | 拆分并保留适配器，不直接向插件暴露整个 preload |
| `plugins/agent-orchestration.ts` | commands/AI/source 投影；工具名正则过滤；普通命令参数为空对象 | 工具成为一等契约，结构化权限与执行守卫 |
| `plugins/manifest.ts` | 声明 host、resourceBudget、capabilities | 区分描述信息、兼容检查与可强制执行的权限/预算 |

### 2.1 生命周期风险：必须用测试确认并处理

当前 loader 依赖 activate 返回 disposer。若 activate 在注册部分贡献后抛错，不能仅凭外层 catch 就证明注册已撤销。重复插件 ID 的检测也应前置到激活之前，避免先执行副作用再发现重复。

这不是“进程级沙箱隔离”：catch 只能捕获对应调用的异常，无法隔离无限循环、未管理的计时器或任意同步耗时。

### 2.2 当前已有能力不是零

保留命令、菜单、面板、皮肤、格式处理器、AI provider、asset source、workspace bridge、依赖检查、profile 与贡献优先级。这些是迁移资产，不需要推倒重写。

## 3. 产品目标、非目标与最终验收案例

### 3.1 目标

P1：第三方插件不修改 `App.tsx`、`builtin/index.ts`、核心节点 switch，即可添加完整业务功能。

P2：导入、预览、后台任务、文档操作、资产查询成为稳定服务，内置功能也通过相同公共契约使用。

P3：部分核心服务可由可信提供者在启动时替换，同时保留不可绕过的校验和授权边界。

P4：插件能声明依赖、配置、工具参数、资源需求，并得到清晰的“不支持/未授权/版本不兼容”反馈。

P5：插件失败、禁用、卸载、版本升级不破坏项目资产与画布文档。

### 3.2 非目标

- 第一版不支持任意第三方代码在 Electron main 内直接执行。
- 不承诺同进程不可信 React 组件可被 JavaScript 沙箱可靠隔离。
- 不支持所有提供者任意时刻热替换。
- 不把 SQLite 连接、setBoards、Node require 或整个 window 桥作为公开 SDK。
- 不为实现 V2 必然升级持久化文档版本；先评估现有 v2 能否安全扩展。

### 3.3 最终验收插件：Sample Asset Inspector

在应用源码树外开发和安装一个测试插件，实现：
1. 注册一种新的测试文件格式。
2. 在受控后台任务中解析并提供真实进度与取消。
3. 创建一种自定义节点，支持拖动、缩放、复制、删除。
4. 提供静态预览与编辑面板。
5. 保存、关闭、重开仍能恢复。
6. 缺失插件时保留节点数据并显示安全占位卡。
7. 通过带参数的命令/Agent 工具批量更新节点，操作可撤销。
8. 插件停用后命令、事件、任务和面板正确清理，资产不被误删。

验收检查 diff：不得为此测试插件新增 `App.tsx` 特判、核心 switch case 或 `builtin/index.ts` 静态 import。允许平台迁移阶段一次性增加通用消费接口，但测试插件本身不能再改宿主核心。

## 4. 目标分层与权力边界

```text
安全启动与恢复层（最小可信基座）
  包校验 / 授权 / IPC 身份 / 安全模式 / 版本与恢复
                    │
插件运行时层
  依赖图 / 作用域 / 激活事务 / 服务绑定 / 生命周期 / 诊断
                    │
业务服务契约
  document / operations / assets / imports / jobs / preview / storage
                    │
服务提供者与功能插件
  默认实现、替代实现、格式插件、节点插件、AI、外部资产源
                    │
UI 宿主与自动化工具
  画布、面板、菜单、命令、Agent/MCP 适配
```

### 4.1 三类插件

| 类别 | 能做什么 | 运行策略 |
|---|---|---|
| 普通功能扩展 | 注册格式、工具、面板、节点，调用授权服务 | 默认走受控执行宿主/桥接 |
| 可信 UI 扩展 | 在应用 renderer 中使用 React 集成界面 | 必须明确标为同进程可信代码，不伪称沙箱 |
| 可信系统提供者 | 实现存储、导入策略、预览等公开服务契约 | 明确授权、启动期绑定、严格兼容与契约测试 |

“内置”不等于可绕过文档不变量。内置代码可有预授权策略，但也应使用统一操作入口，以保证撤销和保存语义。

### 4.2 不可绕过的不变量

- 项目/画板 session 身份与目标校验。
- 文档数据 schema 与操作合法性。
- 资产引用和生命周期一致性。
- 权限检查、路径/网络/进程边界。
- 防止失效任务、旧 generation 和重复提交。
- 已承诺的持久化事务与恢复约束。

提供者可替换，不代表这些不变量可被普通业务 hook 移除。

## 5. V2 Manifest 与包契约

以下为设计草案；最终字段应经 ADR 固定，不能直接当作现有格式使用。

```ts
interface PluginManifestV2 {
  manifestVersion: 2;
  id: string;
  version: string;
  hostApi: string;                     // 明确版本范围语法
  entrypoints: {
    extension?: string;               // 扩展宿主入口
    worker?: string;                  // 后台解析入口
    trustedRenderer?: string;         // 仅可信 UI 模式
  };
  requires?: Record<string, string>;  // 插件 ID → 版本范围
  optionalRequires?: Record<string, string>;
  consumes?: ServiceRequirement[];
  provides?: ServiceDeclaration[];
  permissions?: PermissionRequest[];
  configSchema?: JsonSchema;
  budgets?: ResourceBudgetRequest;
}
```

### 5.1 清晰区分四种概念

- contribution：插件向哪里增加东西，例如一个 node type。
- service dependency：插件需要哪个 API，例如 assets.repository@1。
- permission：插件能访问什么资源，例如用户选定目录或网络域名。
- budget：允许多少并发/字节/任务，不代表同进程可强制限制所有内存。

不要继续让 capabilities 同时承担以上所有含义。V1 的 capabilities 保持原义，由适配器映射到 V2 的贡献描述，不自动授予更高权限。

### 5.2 包结构与安装

第一版可采用本地扩展目录安装：

```text
plugin-package/
  manifest.json
  extension.js
  worker.js
  renderer.js      # 可选、可信模式
  assets/
```

- 入口必须位于包根内，规范化路径，拒绝穿越、逃逸符号链接和畸形压缩包。
- 文件大小、文件数、解压总量设置上限；不默认执行安装脚本。
- 外部代码必须由真正的运行时加载器消费，不能依赖 Vite 构建期 glob 冒充动态安装。
- 依赖打包、共享 React/SDK 单例、模块格式、CSP 与资源 URL 规则必须定义。
- 内容哈希用于识别包是否变化；无签名基础设施时不能把哈希称为可信签名。
- 升级改变权限或入口时重新评估授权；保留上个可用包用于回退。
- 安装不等于自动启用；启用不等于批准所有权限。

### 5.3 版本策略

Manifest、Host API、服务 API、插件版本、节点 schema、项目文档版本分别管理。

插件版本升级不必升级所有服务协议。服务 major 不兼容时拒绝激活并给出缺失能力，不用 unknown/any 掩盖兼容错误。

## 6. 插件作用域与生命周期

建议状态机：

```text
installed → validated → waiting-dependencies → activating → active
                          ↓                    ↓          ↓
                       blocked               failed    quiescing
                                                          ↓
                                                       disposed
```

### 6.1 ScopedPluginContext

```ts
interface ScopedPluginContext {
  readonly pluginId: string;
  readonly signal: AbortSignal;
  services: ServiceConsumer;
  contributions: ScopedContributions;
  events: ScopedEvents;
  operations: ScopedOperationHooks;
  effects: EffectScope;
  jobs: ScopedJobClient;
  logger: PluginLogger;
}
```

插件调用 register/on/provide 时自动归属于当前作用域；不能通过传入其他 pluginId 冒名注册。

推荐提供受管 timer/listener/disposable 帮助器，但须明确：可信同进程插件若自行调用原生 setInterval，平台无法凭空保证自动跟踪。对第三方的保证依赖隔离宿主与桥接，不是仅靠编码约定。

### 6.2 激活事务

1. 激活前校验 manifest、重复 ID、依赖、服务版本、权限和资源可用性。
2. 创建未对外发布的作用域。
3. 执行 activate，可异步、可取消、有限时。
4. 将注册暂存于本次激活事务；成功后按定义原子发布。
5. 失败则反向撤销全部受管注册和任务，保留可诊断错误。
6. 禁止通过“catch 后继续启动”来替代副作用回滚。

全局不可逆操作不能由 activate 任意执行；优先在激活后通过明确用户命令发起。对于已发生的外部网络/文件副作用，文档必须区分补偿与真正回滚。

### 6.3 卸载顺序

- 停止接受新调用，标记 quiescing。
- 取消插件拥有的任务/订阅入口。
- 等待正在执行的调用到达安全结束点；超时按宿主类型处理。
- 卸载 UI/贡献、撤销服务，反向释放资源。
- 提供者有消费者时不能直接卸载：先停依赖方，或要求重启配置。
- disposer 幂等；重复 dispose 不得删除后来注册的新提供者。

同进程同步死循环无法被 AbortSignal 打断；第三方重计算应置于可终止宿主。

## 7. 服务目录、绑定与替换

### 7.1 建议服务目录

| 服务 | 负责 | 不负责 |
|---|---|---|
| `canvas.document` | 画板/节点快照、查询、revision、订阅 | 直接暴露 React state setter |
| `canvas.operations` | 校验操作、目标 session、撤销与提交 | 向插件开放任意 reducer |
| `assets.repository` | 授权资产查询、引用、导入结果 | 原始数据库连接 |
| `imports.pipeline` | 导入批次、解析阶段、处理器、目标 | 重新实现另一个全局队列 |
| `jobs.scheduler` | 执行、进度、取消、许可与背压 | 任意无限线程/任务 |
| `media.preview` | 缩略图、封面、波形、缓存键 | 直接在 renderer 同步重编码 |
| `workspace.storage` | 保存、加载、迁移、提供者身份 | 绕过文档 schema 保存任意结构 |
| `agent.tools` | 带 schema 的工具注册与调用 | 名称黑名单当作授权 |
| `host.files` | 授权文件/目录句柄与流 | 任意 native path 读取 |
| `host.network` | 授权网络请求 | 不受控 fetch 代理 |
| `host.processes` | 可选的授权进程任务 | 默认给所有插件 shell |

服务目录不要一次全部落地；先迁移 document/operations/jobs/imports 的最小闭环。

### 7.2 Provider 绑定

服务定义指定单提供者还是多注册者：
- workspace.storage：当前项目绑定一个 provider。
- format handlers：多个候选，通过确定性优先级解析。
- media.preview：可按格式路由多个 provider，但路由策略唯一且可解释。

使用显式 profile binding，例如 service key → provider ID。冲突时拒绝或要求选择，不能“最后加载者悄悄覆盖”。

第一版核心 provider 只在启动/项目打开时绑定。切换存储提供者需要关闭当前项目或执行显式迁移；不能依靠普通 hot reload 把已有对象交给另一套存储。

### 7.3 服务快照与调用

读取快照不得包含可直接修改的共享内部对象。大文档查询需要分页/索引，不能每个插件每帧复制全量场景。

每次异步调用传播项目 session、调用者身份、requestId、AbortSignal。跨进程不能直接传函数或 AbortSignal，桥接应使用 request ID + cancel 消息实现。

## 8. 文档操作接口与撤销语义

示例草案：

```ts
interface OperationRequest {
  projectSessionId: string;
  boardId: string;
  requestId: string;
  expectedRevision?: number;
  label: string;
  operations: readonly DocumentOperation[];
}

type DocumentOperation =
  | { kind: 'node.create'; node: NodeInput }
  | { kind: 'node.patch'; id: string; patch: NodePatch }
  | { kind: 'node.delete'; id: string }
  | { kind: 'node.reparent'; id: string; parentId: string | null };
```

- 插件不向公共接口提交任意 JavaScript 函数。
- actor/pluginId 由授权上下文注入，不能相信请求中自报身份。
- 所有操作在提交前验证；小批事务要么全通过，要么不提交。
- 同一 requestId 的重试应幂等；不能因网络重试重复建节点。
- revision 不匹配返回明确冲突。只对可证明安全的操作自动重放，不能静默覆盖用户同时编辑。
- 修改后返回 applied/rejected/conflict 的结构化结果、revision 和实际影响 ID，而非只有 boolean。
- undoable 编辑、临时视觉状态、衍生缓存更新需要不同内部通道；公共普通扩展默认只能提交可审计的正常操作。

与导入文档一致：长期导入不能用一份旧 boards 快照回滚。第一版分批提交沿用现有历史；若需要跨多个 flush 的单条历史，独立 ADR，不把同时发生的用户编辑吞并进插件事务。

## 9. 完整节点类型契约

仅注册 React component 不能构成完整节点类型。V2 需要模型、几何、持久化、资源与展示分离。

```ts
interface NodeTypeDefinition<T> {
  type: string;                    // namespaced，例如 vendor.asset-inspector
  schemaVersion: number;
  dataSchema: JsonSchema;
  defaults: T;
  migrate?: NodeMigrationChain;
  geometry: GeometryPolicy;
  assetFields?: readonly AssetFieldDescriptor[];
  capabilities: {
    resize: boolean;
    rotate: boolean;
    editable: boolean;
  };
  renderer: RendererReference;
  preview?: PreviewProviderReference;
}
```

### 9.1 几何热路径

默认卡片使用内核提供的矩形几何：x/y/width/height/rotation，不要求每帧调用插件代码。

非矩形节点可声明受支持的几何策略或可信、同步、有界的适配器。普通隔离插件不能通过异步 RPC 决定每帧 hit-test；可以预计算命中形状并缓存。

旋转 AABB、group/frame、选择框、复制位移与缩放必须使用统一几何工具。旧 image/path/arrow 等先通过内置适配器兼容，不一次迁移全部类型。

### 9.2 持久化

节点至少保存 type、schemaVersion、插件业务 data、通用布局属性及稳定资产引用。

- 不持久化 React 元素、函数、对象 URL、DOM 或任意类实例。
- 迁移按相邻版本链执行，验证后才提交，保留可恢复原数据。
- 未知插件节点原样保留，提供缺失插件占位、名称/边界、可删除/导出原数据等基本行为。
- 未来 schema 版本不能被旧插件强行降级或覆盖。
- 资产字段显式声明，让保存、复制、导出、GC 知道引用关系，不能靠扫描任意字符串猜测 URL。

### 9.3 展示与编辑生命周期

渲染与编辑面板分开；小尺寸/离屏状态优先静态预览。播放器/3D/阅读器激活必须经过资源管理，不能每张卡片自动启动独立重循环。

ErrorBoundary 可以隔离渲染异常，但不隔离死循环或长任务，必须明确其保证范围。

materialization 保持 O(1) 查询；贡献变化时构建新快照并原子交换，用 revision 通知宿主一次更新，不在每次 render 合并 profile。

## 10. 事件与操作扩展链

明确四种机制，禁止混用：

| 机制 | 用途 | 能否改变操作 |
|---|---|---|
| 通知事件 | 已发生事实、诊断、进度 | 否 |
| 异步策略 Hook | 操作前补充/验证/拒绝 | 仅契约允许范围 |
| 执行包装器 | 超时、指标、重试 | 受限，不可绕过核心校验 |
| 最终守卫 | 权限、session、schema 等不变量 | 只能拒绝，不能被后续撤销 |

建议扩展点：import/before-parse、import/after-parse、asset/before-store、canvas/before-operation、export/transform。

每个扩展点文档必须列出：输入 schema、允许变更字段、输出、排序、是否能 short-circuit、超时、AbortSignal、异常策略和递归限制。

规则：
- 输入只读；允许变更时返回新对象。
- next() 最多调用一次；重复调用明确报错。
- 下游安全拒绝不可被上游改成成功。
- policy failure 默认拒绝；纯观察者失败只记录。不能给所有 hook 统一“报错就继续”。
- 串行链排序稳定，priority 相同按 ID 排序，诊断工具可显示顺序。
- 限制递归触发和重入深度，避免 before-operation 再调用同操作无限循环。
- 对外部不可逆动作重试必须声明幂等性；默认不自动重试。
- pointermove、逐帧绘制、几何命中不走通用异步链。

## 11. 权限模型与执行宿主

### 11.1 授权流程

声明需求 → 用户/策略授予 → 创建插件专属 capability client → 每次调用校验实际参数 → 记录可审计结果。

最小权限示例：
- 当前项目资产读；
- 当前项目文档写；
- 用户选择目录下的文件读；
- 指定域名网络访问；
- 指定可执行程序及受限参数的后台任务；
- 注册可信 renderer 界面。

权限不只按插件名字判断，需绑定包版本/内容身份、调用者、目标资源和会话。

### 11.2 运行时保证

- 同 renderer 的可信插件可以直接执行 JS，API 门面无法构成完整安全沙箱。
- Worker 隔离可改善生命周期和 UI 性能，但不能自动等同于完整权限沙箱；仍需限制其可用环境和桥接。
- 不可信 UI 可考虑 sandbox iframe + RPC；与 React 同进程组件是不同模式，需单独设计样式、焦点、剪贴板、拖放和 CSP。
- Node 扩展宿主可隔离崩溃，但若拥有完整系统权限，也不是安全沙箱；需要 OS 约束或可信声明。
- 第一版若暂不具备安全隔离，只允许显式信任的本地扩展，不宣传支持任意不可信第三方代码。

### 11.3 取消名称正则授权

agent-orchestration 中的危险词过滤不能继续作为主要权限机制。替换前先建立结构化执行入口与工具授权测试，再移除误拦逻辑。

一个叫 innocuous 的工具不应因此获得进程权限；一个叫 inspect_network_metadata 的只读工具也不应仅因名称被禁止。

网络授权要校验重定向后的目标、协议和私网策略；文件授权要校验真实路径/句柄与符号链接边界；不能只做字符串 startsWith。

## 12. 命令与 Agent 工具成为一等契约

```ts
interface ToolDefinition {
  id: string;
  title: string;
  description: string;
  inputSchema: JsonSchema;
  outputSchema?: JsonSchema;
  requiredPermissions: PermissionRequirement[];
  effects: 'read-only' | 'document-write' | 'external-side-effect';
  execute: ToolHandlerReference;
}
```

- 工具 ID 与插件 ID namespaced，不能只靠替换非法字符而制造碰撞。
- 调用时校验参数；schema 不是仅提供给模型看的文案。
- UI 命令、快捷键、Agent、MCP 可使用不同入口，但调用同一个受控执行服务。
- 空参数旧 command 可通过 adapter 兼容；复杂工具必须有明确参数 schema。
- 返回结构化错误、取消状态、任务引用和可审计 requestId。
- 长任务返回 job ID，进度和最终结果走 jobs 服务；不让工具调用无限悬挂。
- 输出限制字节数、日志长度和资产内联大小；大数据返回受控引用。
- 删除、外部写入、执行进程等需要明确审批策略，不因来自 Agent 就跳过确认。
- MCP 是协议适配器，不是权限豁免入口。

## 13. 与导入/预览/任务平台衔接

复用 `资产导入非阻塞管线开发规格.md` 的任务模型，不建立第二套 ImportJob。

职责分配：
- 格式插件：识别、解析、报告阶段、产出数据/资产引用。
- 预览插件：生成图像、视频封面、波形等衍生结果。
- jobs.scheduler：并发、许可、背压、取消、所有权。
- imports.pipeline：绑定原目标画板、批次语义、稳定布局、结果提交。
- canvas.operations：校验与撤销。
- assets.repository/storage：入库、去重、保存和恢复。

格式插件不能直接 setElements、跳过队列读取全部大视频或在 renderer 编码无限量图片。

插件返回的预览结果必须包含源内容身份、生成器版本和参数，以形成正确缓存键。升级预览算法不能误复用旧缓存。

resourceBudget 中 maxMemoryMB 在同 renderer 模式只能作为调度估算/诊断提示，不能声称硬限制；可强制执行的并发、响应大小、超时必须真实接入运行时。

## 14. 配置、热更新与诊断

### 14.1 配置

复用现有 profile 分层；增加明确服务绑定，不另造全局配置系统。

配置需要 schema 验证；密钥进入专用 secret 服务，不能明文写入共享 manifest、普通 profile 或诊断日志。

V1 boolean/number/string 配置保持兼容，V2 可逐步支持对象 schema；不能自动把任意未知字段透传到高权限 provider。

### 14.2 热更新等级

- L0：必须重启，例如执行宿主、核心提供者。
- L1：重新打开项目，例如存储绑定/部分迁移。
- L2：可受控重载，例如菜单、皮肤、非核心面板。

每个插件/服务声明所需等级，UI 诚实显示。不必一开始取消当前 staged + reload 管理方式。

### 14.3 插件诊断面板

应能查看：
- 激活状态、失败原因、依赖与阻塞链；
- 服务消费与提供、当前绑定；
- 已声明/已授予权限与拒绝原因；
- 已注册贡献及冲突；
- 活跃任务、订阅与受管资源数；
- hook 执行顺序、耗时、超时和错误；
- 是否需要重启、包版本与可信级别。

导出诊断默认不包含密钥、文件内容、本地绝对路径和用户资产数据。

## 15. 最小安全模式与恢复

外部插件崩溃或启动失败时，保留只加载内置稳定插件的安全模式；能打开项目并显示未知节点占位。

启动配置采用校验后的计划；本轮启用失败不覆盖最后已知可用配置。插件更新失败可回退上个包，但不得用旧 schema 无损假设覆盖新节点数据。

禁用插件不删除其项目数据；卸载包与删除用户数据必须是不同操作。

存储提供者缺失时不能假装使用默认提供者打开同一数据。应给出明确恢复/安装提示，避免错误写入。

## 16. 分阶段实施路线

### V0：重新审计与 ADR（必须先做）

- 读取实际 kernel/loader/manifest/profile/bridge 与既有 ADR。
- 建立“现有贡献 → 消费者 → 核心特判”矩阵。
- 运行基础检查并备份；记录已有未提交/他人修改。
- 编写新 ADR：信任层级、服务所有权、生命周期、V1/V2 兼容、节点数据策略。

验收：明确哪些限制属于安全，哪些是未开放 API；不能只得到一个新增插槽清单。

### V1：生命周期与作用域加固

- 重复 ID 激活前拒绝。
- ScopedContext 自动归属 register/on/provide。
- 激活失败回滚受管副作用。
- 幂等 dispose、依赖卸载策略、取消与超时。
- V1 插件通过适配器继续运行，先迁移一个小插件验证。

验收：部分注册后抛错不留贡献/服务/监听；重复 dispose 不误删新服务；基础功能无回归。

### V2：文档操作与服务 SDK

- 实现 document/operations 最小接口、错误模型、session/revision 校验。
- 迁移一个现有排列/节点操作插件，不再依赖 App 专属业务函数。
- 建立服务目录、版本与 profile 绑定模型。

验收：调用方不能直接修改快照；跨画板/跨 session 请求被拒绝；撤销重做正确；冲突不覆盖用户编辑。

### V3：与导入任务平台打通（本批已实现，见 ADR-048）

- 导入规格 D1–D3 与本文接口共同实施，单一状态/队列所有者。
- 格式/预览处理器注册、受管任务和能力检测。
- 打通一个新增格式 → 任务 → 进度 → 节点提交闭环。

实现：扩展包声明格式（`formats`），宿主按已安装包匹配文件，Worker 后台解析（真实进度/取消，≤2 MiB、≤1000 条/批），单事务节点提交；`ExtensionImportPanel` 观察批次；不新增第二套 jobs 队列。
验收：无需修改 App 新增分支；有界并发、取消、保存正确；仍在 renderer 的 legacy parser 明确标记。

### V4：完整节点定义（本批以声明式 schema 实现，见 ADR-048）

- 建立 node schema、默认几何、序列化、资产字段、迁移、未知节点占位。
- 先迁移一个普通矩形插件卡片。
- 再逐类减少核心 switch 特判，不同时重写全部图形类型。

实现：包内 `node` 声明字段/默认几何/迁移链；SDK 增加 `extension.node.create/update`（schema 校验、惰性迁移、未知类型拒绝）；v2 序列化经既有 `properties` 往返；CanvasElement default 分支通用 schema 卡片，缺失/停用显示占位卡（数据保留）；schema 驱动的通用属性面板。
验收：外部新节点无需改拖动 switch，可复制/缩放/保存/重开；缺失插件不丢数据。

### V5：操作链与 Agent 工具（本批已实现，见 ADR-048）

- 区分通知、策略、执行包装、最终守卫。
- 工具 schema、权限、长任务与参数校验。
- 安全执行路径就绪后，替换名称正则过滤。

实现：`executeGuardedTool` 提供 before/guard/wrap/after 四阶段 + 执行前再授权 + 超时/Abort；`core.operation-guard` 最终守卫（actor 来自 scope、启用状态、`document.write`/`agent.invoke` 授权、操作类型白名单）；扩展工具经 `projectRegistryAsAgentTools(kernel, context)` 带参数投影（参数类型校验、未知/缺参拒绝）；既有名称正则保留但不再是唯一防线。
验收：工具名称与权限无关；拒绝不能被后续 hook 覆盖；错误、超时和取消路径有测试。

### V6：外部包安装与执行宿主（本批落地"数据-only"形态，见 ADR-048）

- 先支持显式信任的本地包，定义真实动态加载方式。
- 再添加受限第三方宿主；明确 renderer/worker/host 实际能力。
- 包校验、授权、升级回退、依赖、CSP、SDK 单例与安全模式。

实现：`manifestVersion:2 + declarative-v1` 数据-only 包（无入口/URL/脚本字段，校验器拒收可执行结构）；localStorage 安装清单（≤16 包、依赖检查、授权只减不增）；设置区通用管理面（安装/启用/停用/卸载/替换版本）；样例 `extensions/sample-inspector/` 在源码树外，宿主无特判。真实脚本宿主、CSP 与 worker 进程隔离仍属后续阶段。
验收：测试插件从应用源码外安装，不改 builtin/index；恶意入口路径和无授权调用被拒绝。

### V7：可信系统提供者替换（本批实现扩展包版本替换契约，见 ADR-048）

- 挑一个边界清晰的服务先替换，例如预览 provider；不从整个画布渲染器开始。
- 实施启动期绑定、兼容性检查与 provider 契约测试。
- 替代 provider 与默认 provider 对相同测试集满足同样不变量。

实现：`replaceVersion` 同 ID 版本替换（保留已授权交集、记录 previous、依赖复检、schema 迁移链承接旧节点）；核心服务目录仍仅限 core provider 启动绑定，第三方 provider 热替换未开放。
验收：只改配置即可切换实现；消费者不改源码；失败时诊断清晰且不会破坏原项目。

### V8：端到端验收和性能回归

完成第 3.3 节验收插件、文档、迁移指南及安全/性能测试。未完成隔离能力时明确标注仅支持可信插件。

## 17. 测试矩阵

### 17.1 生命周期

- activate 注册服务/贡献后抛错，所有受管注册回滚。
- async activate 超时/取消，迟到结果不发布。
- 重复插件 ID 不执行第二份 activate。
- dispose 重复、反向清理、服务替换后旧 disposer 无害。
- 依赖缺失/循环/版本不匹配给出可理解错误。
- 插件停止后不再接受新任务，活跃任务按契约结束。

### 17.2 文档/节点

- 操作 schema、revision、session 与目标画板校验。
- 重试 requestId 幂等，不重复创建节点。
- 插件创建节点后用户移动，后台结果不能覆盖位置。
- 插件节点复制、缩放、旋转、分组/Frame parenting、撤销重做。
- 未知类型、未来 schema、迁移失败保留数据。
- 缺失插件保存再重开，原业务 data 不被丢弃。
- 资产引用在复制、删除、导出、undo/redo 中正确。

### 17.3 操作链

- 确定性顺序、next 调用两次、重入、超时、AbortSignal。
- 最终拒绝不可被包装器返回成功覆盖。
- 观察者错误不改变成功操作。
- 非幂等外部动作不被自动重试。

### 17.4 权限/包加载

- 名称无危险词但请求高权限仍被拒绝。
- 合法带 net/process 等文字的低权限工具不被误拦。
- 包路径穿越、符号链接逃逸、超大解压与伪造 pluginId。
- 网络重定向/私网目标策略与文件真实路径边界。
- 权限撤销后新调用失效；正在执行调用按声明策略处理。
- 插件升级新增权限需重新批准。
- 安全模式不执行外部插件，仍可显示缺失节点。

### 17.5 端到端与性能

- 完整验收插件从安装到保存恢复。
- 100/1,000/5,000 节点，固定可见量与不同可见量分别测试。
- 插件数从 0/10/50 增加，拖动热路径不能变成每帧扫描全部贡献。
- 导入期间任务 UI 更新不导致全画布频繁重渲染。
- renderer materialization 仅在 revision 变化时更新。
- 反复启用/禁用插件，资源与监听数量不持续增长。
- Worker/宿主崩溃不导致文档静默损坏。

测试应使用 fake clock/fake provider 确定性覆盖竞态；真实 UI/IPC/播放器必须另做集成测试，不用源码正则代替。

## 18. 性能约束与可测指标

- 拖动时不遍历插件依赖图、配置或服务目录。
- 几何命中不依赖异步 RPC；常规节点使用预编译/内核默认几何。
- 任务进度合并发布，参考导入规格的 5–10Hz 起始值。
- 工具/Hook/IPC 返回值与队列大小有预算。
- 同进程 maxMemoryMB 不能承诺为硬上限，必须明确估算与实际隔离差异。
- 记录 pointer/drag frame p50/p95、长任务、React commit、服务调用耗时、RPC 次数、任务排队、资源清理。
- 与同机同场景迁移前比较；不要用注册表微基准声称整机 60fps。

插件平台升级不得把当前性能问题转化为“每一步都跨进程/遍历中间件”。能力开放以稳定控制面为主，渲染和交互数据面保持精简。

## 20. 禁止的捷径

- 向所有插件提供 setBoards、数据库连接、Node require、任意 fs/shell。
- 只把更多名字加入 SLOTS 就宣称核心可替换。
- 换 Cordis 但业务仍全部直接依赖 App 内部闭包。
- manifest 写 worker/main，就认为已有对应执行宿主。
- catch activate 错误，却留下部分已注册贡献。
- 用工具名称正则代替真实权限。
- 把无限异步 Hook 放进 pointermove。
- 外部插件通过修改 builtin/index 才能安装。
- 热卸载正在提供文档/存储服务的插件，没有消费者退出或迁移协议。
- 未知节点直接过滤掉，以便旧类型校验通过。
- 插件版本变化时强行原地改写用户数据，没有失败保留。
- 在同进程运行任意第三方 JS，却宣传强沙箱和硬内存配额。
- 为插件新增功能随意放宽 IPC origin/path 检查。
