## 本次连续完成的两部分

### 1. 旧服务活引用修复

App 的 canvas.export-source / canvas.mutation / canvas.view-state 不再把最初 render 的对象直接注册给 Kernel。新增 `provideLiveService` 稳定方法 facade，每次调用都读取最新 ref，连已经缓存下来的方法也不会停留在旧画板/旧状态。原方法的 this 绑定保留；清理后旧 facade 报错，旧 disposer 不会删除新登记。App 注册中途失败会反向撤销先前成功项；SDK provider 接线也补了部分注册失败清理。

这是 legacy 兼容性修复，不把旧 mutation 接口升级成权限边界。其他 legacy 原始快照与非受管调用仍不具备现代 SDK 的校验保证。

### 2. 节点结构原子事务

在原几何 patch 上增加：

| 操作 | 本批语义 |
|---|---|
| node.createText | 创建已有内建 text 类型；校验文本/位置/尺寸/字号/hex 颜色/新 ID/父级；不允许资产或未知字段 |
| node.delete | 显式删除节点，不删除资产文件，不释放 undo/redo 需要的资产；不隐式级联 |
| node.reparent | 目标只能是 frame/group 或 null；校验最终父子图，无环、无悬空引用 |
| node.patchGeometry | 保持原有几何范围；同时保护锁定祖先，不允许借子节点修改绕开锁定容器 |

一批可混合这些操作，全部校验通过后才提交，并只写一条既有 operationHistory。每个节点一批最多一个操作；需要修改刚创建的文本时直接在 createText 输入中提供最终字段，不采用 create 后再 patch 同 ID 的隐式顺序语义。

删除容器必须显式处理其子孙：在同一批删除或移出剩余子节点，否则整批拒绝。reparent 保持当前世界坐标，不自动移动/缩放子孙；复杂 group 变换仍不是本批目标。

公开快照增加只读 parentId 与节点自身 isLocked，方便调用者构造结构操作。ancestor 锁定仍由提交端检查。App 删除提交后只清理当前目标画板的相关选区；换板后不按同名 ID 误清其他画板选区。

## 数据、生命周期与预算

- 继续使用现有 document state、session/revision、commitCanvasOperation、serializeProjectDocument；未创建第二套文档、历史、数据库或任务队列。
- 字段校验先于 dedupe；状态规划在 session/board/revision/dedupe/busy 检查之后。重复请求在节点已删除或已 undo 时仍返回第一次结果，不重新执行。
- 每批最多 1000 节点；单文本最多 65536 字符、全批文本最多 131072；单节点最多 4096 点、全批最多 32768 点。
- dedupe 缓存上限为 256 项且估算 UTF-16 字符串体积不超过 8 MiB，先触及者触发淘汰。这不是整个 JS heap 的硬配额。淘汰后的过期请求仍被 revision 拒绝；不提供跨进程/重启 exactly-once。
- 新建 ID 限 ASCII 安全字符 1..128；操作既有节点/父级仍接受有界非空 Unicode ID（含空格），避免为了新节点规则破坏旧项目中的 ID。
- createText 不接受 locator/assetId，任意媒体节点创建必须等待资产所有权接口，不能绕过受管存储。
- 当前目录仍只有真实核心 provider，未开放第三方替换。SDK 是可信同进程门面，不是恶意 JS 沙箱。
