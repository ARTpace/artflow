## 四、插件开发体验（DX）参照（2026-09-22 调研）

- 现状：builtin 插件开发 = manifest.json + activate(ctx) + 注册表加一行，vite HMR 秒生效，限制仅 TS/命名空间 id/manifest 纪律——难度低于 Obsidian（需 esbuild 打包）与 Blender（Python 模块规范 + 手动重载）
- 业界规律：①元数据走独立声明文件（bl_info→blender_manifest.toml 轨迹，我们已到位）；②第三方插件依赖必须随包自带（Blender wheel / Obsidian esbuild 全量打包），禁止共享宿主依赖，P4 照做；③命名空间均被冲突逼出（Blender 4.2 加 bl_ext.<仓库> 前缀），印证 <ns>.<name> 强制 id；④难度分水岭在沙箱与否：Obsidian/Blender=不隔离+审核/权限声明，AssetLibrary=沙箱+JSON-only，P4 按 builtin/restricted 三档取折中
- DX 状态：R7 已交付最小 `definePlugin()` helper；插件模板目录仍后置，避免只为模板重构现有 builtin。

### 契约演进策略（防大版本更新坏插件，参照 VS Code engines / Obsidian minimumAppVersion）

1. 契约只加不改不删：SkinTokens/FormatHandler 等契约只允许新增可选字段，禁止改名/删除/收紧类型 → 老插件永久兼容
2. MANIFEST_VERSION 并行窗口：出 v2 时 loader 同时支持 v1+v2 过渡，不切换即断
3. R7 已为 manifest 增加 `minHostVersion` 字段（plugin contract API version）：不兼容 builtin 单独跳过并警告；完整插件列表 UI 后置
4. 弃用周期：移除插槽/字段前先控制台警告跑两个小版本
5. 数据优先贡献（纯 JSON）在宿主重构中存活率最高——架构已押注
6. P4：第三方插件版本进 lockfile（dsh profile 模式），宿主升级后旧环境可回退
