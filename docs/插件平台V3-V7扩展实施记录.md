# 插件平台 V3–V7 扩展实施记录

2026-09-23｜ADR-048｜声明式扩展宿主一次连续交付；V8 端到端真机/性能验收未完成

## 本次连续完成的五个阶段

### V3：格式 → 受管后台任务 → 节点提交

- 扩展包声明 `formats`（样例为 `.insp` json-lines）。`useFileHandlers` 在既有流程最前把匹配**已安装且启用**扩展的文件整体路由到受管导入，不再走旧同步解析；不匹配的文件原路径不变。
- 批次状态机挂在扩展运行时上（≤8 批、≤64 文件/批、≤1000 记录/批）：解析 → 条目标记 → 单事务提交。解析在真实后台 Worker 中执行：分块读取（≤2 MiB）、逐步进度、30s 超时、AbortSignal 取消并终止 Worker。
- 提交是一次文档事务（`extension.node.create` × N，requestId=`ext-import-<batchId>` 幂等，revision 冲突拒绝）。解析失败只标记对应文件条目；提交失败整批不产生节点。`ExtensionImportPanel` 只做观察/取消，不拥有状态。
- 没有新增第二套 jobs 队列；与既有受管资产导入队列并行但互不替代。

### V4：动态节点 schema / 保存迁移 / 占位

- 包内 `node` 声明字段（string/number/boolean + 默认值）、默认几何与迁移链（样例含 v1→v2 `titleText`→`title` 重命名）。
- SDK 新增 `extension.node.create` / `extension.node.update`：未知或停用类型 NOT_FOUND（绝不凭空创建）；数据按 schema 类型校验，未知/伪造字段、非有限数、超限（单条 16K、键 ≤32）拒绝。
- 惰性迁移：存储版本落后时首次触碰按迁移链就地升级（缺失迁移/字段冲突→拒绝并保留原数据）；版本超前同样拒绝并保留数据。
- 持久化不改 v2 算法：扩展字段经既有 `properties` 通道往返（检查覆盖序列化→反序列化→再序列化）。
- CanvasElement default 分支对 `ext.*` 渲染**通用 schema 卡片**（无每扩展组件）；停用/缺失时占位卡并保留数据展示；选中扩展节点出现 schema 驱动的属性面板，改动经 SDK 事务提交、可撤销。

### V5：操作链最终守卫 + 带参数工具

- `executeGuardedTool`：before → guard（最终拒绝）→ wrap（可嵌套）→ execute → after；execute 前再 authorize（执行中授权被撤即中止）；超时与外部 AbortSignal 全程生效。
- `core.operation-guard`（builtin.core-extensions 注册于 `hooks` 槽，priority 1000）：actor 必须来自可信 scope；agent/command 面要求包启用 + `document.write`（写操作）+ `agent.invoke`（agent 面）；操作类型白名单。guard 拒绝不可被后续包装器覆盖。
- 扩展工具投影：命令（命令面板可用，停用即移除）与 Agent 工具（`projectRegistryAsAgentTools(kernel, context)` 第 4 段，仅启用且具 `agent.invoke` 的工具；参数按 schema 类型校验，未知/缺参/非有限数拒绝）。原名称正则保留但不再是唯一防线。

### V6：数据-only 外部包宿主

- `manifestVersion:2 + declarative-v1`：无入口/URL/脚本字段；校验器拒收可执行结构、越权 ID、重复字段、超尺寸包（≤64K）、非法依赖环。
- localStorage 安装清单：≤16 包、依赖启用检查、停用/卸载依赖保护、深冻结。
- 设置区「Extension packages」通用管理面：粘贴 JSON 安装、启用/停用、版本替换（粘贴新版本）、卸载（节点数据保留提示）。
- 样例 `extensions/sample-inspector/`（package.json + sample.insp + README）位于**源码树外**，不被任何模块静态 import；宿主无特判、无核心 switch、无 builtin 特判。

### V7：版本替换契约

- `replaceVersion`：同 ID 替换，授权取交集（只减不增）、记录 `previous`、依赖复检、迁移链承接旧节点；核心服务目录第三方 provider 热替换**仍未开放**（仍仅 core provider 启动绑定）。
