# Artflow 用户数据层架构方案（对标 Blender）

> 日期：2026-10-09 ｜ 性质：架构方案（待评审）｜ 关联：`docs/设置系统升级开发文档.md`（交互层，本方案补它缺的**存储层**）
>
> **一句话目标**：把 artflow 从「跑在 Electron 里的浏览器应用」变成「Electron 桌面应用」——
> 用户数据不再归浏览器存储（LocalStorage，按 origin 隔离），而由主进程以**文件**持有，
> 渲染层退化为纯视图。对齐 Blender 的 config 目录模型。

---

## 0. 结论先行

| 判断 | 说明 |
|---|---|
| 工程数据层**已经很完备** | `storage/projectRepository.cjs`：SQLite + 内容寻址 blob + 派生物 + 导入作业 + R-Tree 空间索引 + schema 迁移。这块**不用动**。 |
| 缺口在**用户数据层** | 语言 / 皮肤 / 快捷键 / 密钥 / 画布视图 / 主题收藏 / 外插件开关 …… 共 **18 类键**全部散在渲染层 `localStorage`。 |
| 症状根因 | LocalStorage 按 **origin + Chromium profile** 隔离；dev(4002) / 打包(file://) / 换端口 = 三份互不相干的用户数据。任何一次解析失败还会**静默回退默认值**。 |
| 已开的口子 | 插件开关已迁到主进程 `plugin-profile.json`（2026-10-09），本方案是把它**推广成统一层**。 |
| 建议路线 | P1 地基（配置根 + 通用 ConfigStore + IPC + 渲染层 store）→ P2 存量键收敛 → P3 桌面化能力。 |

## 2. 对标 Blender

| Blender | 作用 | Artflow 对齐 |
|---|---|---|
| `userpref.blend` | 用户偏好（全局，跨工程） | `config/preferences.json` |
| `startup.blend` | 启动文件 / 新建初始态 | `config/startup.json`（工作区初始布局） |
| `config/`（按版本分目录） | 配置根 | `userData/config/` + `schemaVersion` |
| `scripts/addons/` | 第三方插件 | `config/plugins.json`（扩展开关） |
| `extensions/` + manifest | 扩展系统 + 仓库 | 已有 `artflow.extensions.v2` + manifest |
| `presets/` | 预设（导出/导入设置） | `config/presets/` |
| `datafiles/` | 内置资源 | 项目内数据（不迁移） |
| `temp/` | 会话临时文件（可重建） | `userData/temp/` |
| `recent-files.txt` | 最近文件 | `config/recent-files.json` |
| `.blend1` | 上一版备份 | `*.json.bak`（写前备份） |
| `--factory-startup` | **忽略用户配置启动** | `ARTFLOW_SAFE_MODE=1`（排查神器） |
| 崩溃恢复 `quit.blend` | 会话恢复 | 已有 `banana-session.json` 雏形 |

**Blender 的四条架构精髓（我们要抄的）**：
1. **配置根单一**：所有用户数据在一个根下，有明确归属，不散落。
2. **偏好与文档分离**：`userpref` 全局，`.blend` 属于工程。二者生命周期不同。
3. **原子写 + 上一版备份**：写完 `.blend1` 兜底，损坏可回滚。
4. **有逃生门**：`--factory-startup` 让"配置污染导致打不开"永远可解。

## 3. 目标架构

### 3.1 配置根结构（`app.getPath('userData')` 下）

```
%APPDATA%\artflow-zho\
├─ config\                       ← 用户配置根（对齐 Blender config/）
│  ├─ preferences.json           全局偏好（语言/画布/生成默认值/输入/外观选择）
│  ├─ preferences.json.bak       上一版（.blend1 对齐）
│  ├─ plugins.json               插件 + 扩展开关（plugin-profile.json 迁入）
│  ├─ workspace.json             面板布局 / 列宽 / 分割条 / 收起记忆 / 主题收藏
│  ├─ skins.json                 每皮肤逐项配置（从 bp-skin-config.* 汇总）
│  ├─ secrets.json               API key 等（独立文件 + 权限收紧）
│  ├─ recent-files.json          最近工程（对齐 recent-files.txt）
│  └─ presets\                   设置预设导出（对齐 presets/）
├─ projects\                     ← 工程（或用户自选路径，`.artflow/` 内容寻址库）
├─ logs\                         ← 已有：electron.log
├─ temp\                         ← 会话缓存 / 中间产物（可随时整目录删）
└─ (Chromium 自身目录：Local Storage / Cache / IndexedDB —— 不再放用户数据)
```

### 3.2 分层职责

| 层 | 职责 | 禁止 |
|---|---|---|
| **渲染层**（React） | 只调用 `preferencesStore` / IPC，渲染视图 | 直接碰 `localStorage`、直接读文件 |
| **契约层**（TS 类型 + IPC 通道） | `PreferencesStore` 接口、通道白名单、schema 类型 | 手写裸通道名 |
| **主进程**（Node） | **唯一写者**：原子写、备份、schemaVersion 迁移、校验 | 被渲染层绕过 |

### 3.3 契约草案

```ts
// plugins/preferences-store.ts（渲染层薄适配，后端可换）
export interface PreferencesStore {
  get<T extends PrefValue>(key: string, fallback: T): T;
  set<T extends PrefValue>(key: string, value: T): void;   // 同步落盘 + 通知
  subscribe(key: string | null, fn: () => void): () => void;
  exportAll(): string;                                     // 预设导出
  importAll(json: string, mode: 'merge' | 'replace'): void;
  readonly source: 'host-file' | 'local-storage-fallback'; // 来源自证
}
```

```js
// main/configStore.cjs（主进程，通用）
// 单文件卷：{ schemaVersion, revision, values: { [key]: value } }
createConfigStore({
  filePath,            // .../config/preferences.json
  schemaVersion,       // 版本化：只加不改 + migrate(prev, next)
  defaults,            // 默认值表（重置目标 + 缺失补齐）
})
// → read() / get(key, fallback) / set(key, value) / patch(obj) / reset(keys) / stats()
// 原子写：写 .tmp-<pid> → fsync → rename；写前把旧文件复制为 .bak
// 读失败：优先回退 .bak，其次 defaults；任何回退都返回 { degraded: true, reason }
```

**三条不可破的语义**（沿用 `plugin-profile.json` 已验证的做法）：
1. **同步契约**：`set` 在渲染层是同步的，写失败必须**同步抛错**给 UI（走 `sendSync`，不用无人 await 的 `invoke`）。
2. **备份优先于重置**：损坏时回退上次可用快照，**绝不**静默重置成默认值。
3. **降级可见**：任何回退都带 `degraded/reason`，写进 `logs/electron.log` 并在设置页提示。

## 4. 分阶段路线

### P1 · 地基（不动业务，先通一条真链路）

1. `main/configStore.cjs` —— 通用文件配置存储（原子写 / 备份 / schemaVersion / migrate / defaults）。
2. `main.cjs` —— 新增 `config:{read-sync, set, patch, reset, stats}` 通道；`trustedRenderer` 校验；启动诊断日志。
3. `preload.cjs` + `types.ts` —— 暴露 `window.artflowConfig`，仅白名单操作，补类型声明。
4. `plugins/preferences-store.ts` —— 渲染层单例 store，后端走主进程；桥不可用（纯浏览器 vite）时**自动回退 localStorage**。
5. **首个消费方**：把 `language` 切过去，验证"改语言 → 重启 → 仍是该语言"，并确认落盘文件存在。

> 验收：`tsc` 零新错；`vite build` 通过；隔离实例实测重启保持；旧 localStorage 数据自动迁移且不删除。

### P2 · 存量键收敛（一次一个，逐个验）

按风险从低到高：`perfHud` → `bp-boot-errors`（改走 logs/）→ `userEffects` → `wheelAction` / 快捷键 → `canvas-view` → `skin-state` / `skin-config` / 主题收藏 → `external-plugins` / `extensions` → `geminiApiKey`（最后，需单独裁决）。

- 每项都用 **legacy adapter**：读旧 key、写新后端，**零迁移风险**；确认稳定后再删旧键读写。
- 每项都补一条 `scripts/check-*.cjs` 回归。

### P3 · 桌面化能力（Blender 有而我们没有的）

**状态：六项全部已实现。** ① `ARTFLOW_SAFE_MODE=1` → R41 / `docs/adr/ADR-053`；②–⑥ → R45 / `docs/adr/ADR-054`。

| 能力 | 价值 | 落地物 |
|---|---|---|
| `ARTFLOW_SAFE_MODE=1`（--factory-startup） | 忽略用户配置启动，秒级排查"关不掉的插件 / 打不开的皮肤"（**已实现**：R41 / `docs/adr/ADR-053`） | `main/safeMode.cjs` |
| 工作区布局持久化（`workspace.json`） | 面板/列宽/分割条跨重启保持（主人长期诉求）（**已实现**：R45 —— 面板开关 + 侧栏标签 + 设置页最后分组；**列宽与分割条位置尚未纳入**） | `plugins/workspace-layout.ts` + `hooks/useWorkspaceLayout.ts` |

## 5. 关键设计裁决

| 裁决 | 选择 | 理由 |
|---|---|---|
| 存储后端 | **主进程文件**（非 electron-store） | `main/*.cjs` 零三方依赖；electron-store v9+ 是 ESM-only，CJS 拿不到；且我们要的"损坏回退快照而非重置默认"它不提供。原子写仅 3 行。 |
| 通道粒度 | **通用 kv**（`config:set`）而非每功能一通道 | 通道爆炸 = 维护面爆炸；用 key 前缀分域（`canvas.*` / `appearance.*`），schema 由主进程 defaults 表兜底。 |
| 文件切分 | 按**写入频率与敏感度**切（preferences / workspace / recent-files / secrets） | 单文件重写整篇；把高频小值与大块皮肤配置分开，避免写放大。敏感度是第二个判据：`secrets` 单独成卷才能对它单独收权限 / 单独加密，而不牵连整份偏好。 |
| 密钥加密粒度 | **值级**（`createConfigStore` 的 `valueCodec` 钩子）而非整文件级 | 文件级会让 `stats()` 数不出键名与字节，而存储管理面板正需要这两项。自描述前缀 `enc:v1:` 让"是否密文"不依赖任何额外元数据 → P1/P2 已落盘的明文 `secrets.json` **零迁移**即可读；将来换算法只需 `enc:v2:`。 |
| 预设可携带的卷 | **仅 `preferences` + `workspace`**（`PRESET_VOLUMES`） | 预设是可分享/可外传物：带 `secrets` = 泄钥；带 `recent-files` = 换机后满屏死链。这是**安全边界**，不是功能裁剪。 |
| 预设导入的生效时机 | 落盘 + 显式提示"**需重启**"（提供一键重启） | 语言 / 外观 / 皮肤活在模块级单例里，重写文件不会让它们重新求值。与其给一个"改了一半"的迷惑状态，不如说实话。 |
| 不可解密的历史密钥 | 移出 `values` 但保留在 `preserved`，写回时**原样合并** | 否则"用户正常保存一次"就会把磁盘上的密钥抹掉（不可逆）。渲染层永远看不到密文，`preserved` 只活在主进程。 |
| 钥匙串不可用时 | **写失败并抛错**，绝不静默写明文 | "用户以为加密了其实没有"是最坏结果。这是"同步抛错契约"里唯一一处刻意的不对称。 |
| 清空缓存的边界 | 只动 `userData/temp`，主进程路径守卫（`basename === 'temp'` 且位于 `userData` 下） | 缓存可重建，工程数据不可。渲染层传什么路径都不越界。 |
| 旧数据 | **保留不删**，legacy adapter 双向读写 | 可一键回退，迁移期零风险。 |
| 版本化 | `{ schemaVersion, values }` + 迁移函数注册表 | 只加不改；`schemaVersion` 高于当前 → 拒绝写入并告警（防新版降级破坏）。 |
| 多实例 | 沿用单实例锁；`ARTFLOW_ALLOW_MULTI_INSTANCE=1` 为逃生门 | 多实例共写同一配置文件会互相覆盖。 |
| 安全模式 | `ARTFLOW_SAFE_MODE=1`：**读空 + 只读会话 + 不采纳旧键**；判定收在 `main/safeMode.cjs` 一处并**注入**给各卷 | 用户数据成为真数据之后，"某一条数据把应用搞坏了"必然发生，需要一个秒级二分手段（对标 Blender `--factory-startup`）。三条语义缺一不可：只读第一条，数据会从"旧键采纳 / 旧键迁移 / 外部插件装载"另外三条路自己回来。宿主拒写避免一次"顺手保存"覆盖真实配置；渲染层不抛错是为了保住"干净日志"这个安全模式的全部意义。详见 `docs/adr/ADR-053`。 |

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 同步 `sendSync` 阻塞渲染 | 仅启动期读一次 + 写时单键；不整篇同步读。大文件（skins）分文件后单次写入可控。 |
| 迁移期双写不一致 | 单向权威：**后端为主**，旧 key 只写不读（读优先新后端），迁移完成后停写。 |
| 皮肤引擎改造面大 | 皮肤是"读多写少 + 有内存态"，P2 最后做，先只把 `bp-skin-state` 切过去，逐项配置留后。 |
| 用户正在使用的实例 | 全部改动走隔离 `userData` 探针验证，不触碰用户实例。 |

---

## 7. 本方案不做

- 不做云端同步（配置只在本机）。
- 不做多用户 / 多配置文件切换（Blender 也是单用户配置）。
- 不动 `ProjectRepository`（工程数据层已达标）。
- 不引入状态管理库（zustand 等）——store 保持 ~150 行自研，依赖最小化。
- 不重写快捷键裁决链 / 皮肤引擎既有语义（只换存储后端）。
