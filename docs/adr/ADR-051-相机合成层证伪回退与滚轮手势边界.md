# ADR-051：相机合成层方案证伪回退——transform 回内层 `<g>`，滚轮手势不得打断鼠标手势

- 状态：已采纳（2026-09-23，P2 后续）
- 相关：ADR-049（相机合成层与中档纹理预算——本批回退其前半，保留后半）、ADR-043（视口手势标记不得进入元素渲染依赖）、ADR-050（视口裁剪重挂必须恢复最后显示源）
- 上游文档：`docs/实施迭代台账.md`
- 自检：`scripts/check-camera-compositing.cjs`（断言翻转为"<g> 载体"契约）、`scripts/check-image-preparation.cjs`（重挂记忆，ADR-050）
- 探针：`scratch/probe-svg-root-hit-test.html`（排除命中测试假说，无头可复现）

## 背景

ADR-049 把相机 transform 从内层 `<g>` 移到 `<svg>` 根元素（`will-change:transform`
提升合成层，期望 pan/zoom 每帧只更新变换矩阵、不重栅格化）。真机复测结果**恶化**：

| 真机症状 | 机制 |
|---|---|
| 滚动缩放"很闪" | `<svg>` 层 bounds 覆盖 overflow:visible 下全部世界内容（巨型单层）；缩放时栅格比例失配，手势中显示**旧比例栅格**，比例跨过阈值瞬间整层换新栅格 —— 新旧两套画面交替 |
| 图片消失 | 新暴露区域对应的瓦片尚未按新比例栅格化 → 合成器显示空白 |
| 滚动/拖动"突然失效" | 比例变化触发整层重栅格（成本 = ADR-049 声称省掉的每帧重栅格，只是从"每帧"变成"每次比例失配"且单次更贵），主线程/合成器饱和，输入事件排队 → 界面停滞 |

ADR-049 自己已记录"变换稳定后浏览器按新比例重新栅格化"——几百张图时这正是它想省的成本，
且伴随 stale 画面；合成收益只存在于"栅格比例不变"的窄区间，与无限画布的连续缩放根本冲突。

## 排除过程（防止又一次假归因）

| 假说 | 结论 | 证据 |
|---|---|---|
| transform 挂 svg 根破坏子元素命中测试（→拖动失效） | **排除** | `scratch/probe-svg-root-hit-test.html`：盒内/盒外（overflow:visible）子元素 `elementFromPoint` 均正常命中（命中测试是布局层行为，无头结果可信） |
| 坐标换算漂移 | 排除 | P2 diff 复核：12 处换算全部切到 `getCanvasScreenRect`（外层未变换容器），且 svg 根变换后容器是唯一稳定基准 |
| prepared 换源空窗 | 排除 | 队列"保留旧图直到新源解码"语义自洽（ADR-050 已核查） |
| 重挂从 fallback 起步的边缘闪 | 部分成立，已由 ADR-050 修复 | 但解释不了视口中央的闪与输入失效 |

## 决策

1. **回退相机载体**：transform 回到内层 `<g>`（store 模式 imperative 独占、无 store 模式 React 渲染，
   与 P2 前完全一致）。`<svg>` 根不携带 transform / transform-origin / overflow / will-change。
2. **保留 ADR-049 后半**：512px 中档纹理不变 —— `<g>` 方案每帧重栅格的成本由纹理字节 1/4 化压低，
   这才是对"图片一多才卡"的正确解；同时保留 `getCanvasScreenRect` 统一换算（对两种载体都正确）。
3. **滚轮手势不得打断鼠标手势**（真机"拖动突然失效"的第二个来源，状态机洞）：
   - `endWheelGesture` 不再无条件 `setIsInteracting(false)` —— isInteracting 是鼠标手势的状态，
     滚轮路径从没置 true，也不能抢着置 false；仅当 `interactionMode.current` 为空时复位。
   - `handleMouseDown` 入口**结清悬着的滚轮手势**（取消 rAF、清空闲定时器、flush 最后一个滚轮样本、
     `endWheelGesture`），保证 200ms 收尾定时器永远不会在拖动进行中触发。
4. `check-camera-compositing.cjs` 断言翻转为新契约（载体是 `<g>`、svg 根禁止相机样式、
   helper 换算守卫保留）。

## 后果

- 交互回到 P2 前的已知流畅基线（主人原话："上一次还能流畅滚动缩放，只是图片一多才卡顿"），
  中档纹理把"图片一多"的那部分成本压到 1/4；重挂记忆（ADR-050）消掉边缘闪烁。
- 合成层思路**封存**：除非把内容按视口切成多个小合成层（每层 bounds 有界、栅格比例跟随各自视口），
  否则"单个巨型合成层 + 连续缩放"在 Chromium 上没有出路。后续若重拾，必须先在真机证明
  栅格比例失配问题不存在。
- 已知边界：本 ADR 的症状归因来自真机症状与机制推演 + 合成器行为文献，未做逐帧 trace；
  若回退后仍有残余闪烁，下一嫌疑是 LOD 换档波（ADR-042/043 的历史战场），按"边缘 vs 中央"定位。

## 反证（确认断言不是假绿）

| 反证 | 结果 |
|---|---|
| 把 transform 写回 `svg.style.transform` | `check-camera-compositing` 断言失败 |
| `<svg>` 根加回 `overflow:'visible', willChange:'transform'` | 断言失败 |
| `endWheelGesture` 恢复无条件 `setIsInteracting(false)` | 源码契约由 ADR-050 的 mouseup 路径与交互标记守卫覆盖（`!interactionMode.current` 条件被移除即失效——由代码评审保证，无独立守卫，见"已知边界"） |
