# ADR-057 · 导入准入阈值外置为插件参数

- 状态：已采纳
- 日期：2026-10-10
- 关联：`plugins/format-limits.ts`（新增）、`builtin/formats-book/*`、`builtin/formats-packaged/*`、`builtin/formats-pureref/*`、`scripts/check-core-foundations.cjs`

## 背景

用户导入Z-Library 的 `.epub` 与 `.mobi` 连续失败：

```
Could not import files. No files were placed. Stopped at "...mobi". Palm documents are limited to 8 MiB.
Could not import files. No files were placed. Stopped at "...epub". EPUB files are limited to 16 MiB.
```

排查发现限制是 ADR-029 刻意设的准入闸门（防止 zip bomb / 超量条目打爆渲染层内存），
**但阈值全部写死在各解析器里**，带来三个问题：

1. **数值主观且无安全理由。** 最典型的是 MOBI 8 MiB —— 它比 EPUB（16 MiB）更严，
   而 palmDoc真正的内存护栏另有其人（`MAX_TEXT_BYTES` 4 MiB 解压后文本 +
   `MAX_TEXT_RECORDS` 512）。源文件卡8 MiB 纯属手写，Z-Library 的中文 mobi
   常见 15–40 MiB，被整批挡在门外。
2. **用户无处可调。** 遇到「导入失败」只能改源码重编。
3. **同格式主进程/渲染层差 32 倍。** 同一个 `.cbz`：新版懒加载路径
   （`main/comicArchiveController.cjs`）允许 512 MiB，旧版全量路径
   （`builtin/formats-packaged/packedArchive.ts`）只允许 16 MiB，
   差异从哪来没有任何文档说明。

## 决策

### 1. 阈值收进唯一真相源 `plugins/format-limits.ts`

数字只在 `FORMAT_LIMITS` 定义一次，每个阈值是一条 `FormatLimitSpec`：
`pluginId / key / label / defaultMiB / minMiB / maxMiB`。

**默认值调整**（取舍依据写进代码注释，不靠口头记忆）：

| 格式 | 旧（写死） | 新默认 | 理由 |
|---|---|---|---|
| 纯文本 .txt/.md | 1 MiB | **8 MiB** | 无解压步骤，仍最严，但不再小到挡住正常文件 |
| MOBI/AZW | 8 MiB | **32 MiB** | 旧的 8 MiB 无安全理由；真正的闸门是解压后文本上限 |
| EPUB | 16 MiB | **64 MiB** | 章节有`MAX_EPUB_TEXT_BYTES` 4 MiB 兜底，源文件 16 MiB 偏紧 |
| 漫画（旧全量路径） | 16 MiB | **128 MiB** | 与主进程 512 MiB 同属一个配置缝，量级一致 |
| PureRef .pur | 64 MiB | 64 MiB | 本来就最宽松，数值不变但**变得可调** |

### 2. 放宽源文件上限 ≠ 放宽内存

**条目数 / 单条目字节 / 总文本字节 / 页数这些护栏一律不动。** 区分清楚两件事：

- 源文件上限 = 「读多少容器字节进内存」→ 可调，主人自己负责；
- 解压后护栏 = 「展开后占多少内存」→ 固定，是真正的安全边界。

这条分界让「调大阈值」变成一个可控动作，而不是拆安全阀。

### 3. 漫画两条路径**不强行对齐**

旧全量路径不直接对齐主进程的 512 MiB，因为**内存模型根本不同**：
主进程按需读单页句柄（`MAX_OPEN_HANDLES=6`、页缓存 64 MiB），
旧路径把每页解成 data URL **全量进渲染层**。
统一的是「范围一致 + 语义可查」，不是数值相同。真正要支持超大漫画应走新版懒加载路径。

### 4. 接线用模块级 provider，不改公共契约

`FormatHandler.parse(file)`签名里没有 kernel。为一个可配置项去改全部格式插件的
公共契约 + 类型 + 契约测试，属于「为了配置项改架构」。

选择：解析器从`plugins/format-limits.ts` 的模块级 provider 读阈值，
由各插件在 `activate` 里调`bindFormatLimitConfig(ctx)` 注入，返回 dispose 随插件停用一起摘掉。

**明确拒绝的两个方案**：
- 直接读 localStorage → 绕过 profile 的`configSchema` 类型校验与依赖停用判定，
  且踩ADR-055 记录的「localStorage 按 origin 隔离」坑；
- 把 kernel 穿进解析器签名 → 同上，改公共契约。

provider 为 null 时解析器回退契约默认值，**因此永远可独立单测**，不依赖宿主状态。

### 5. manifest 声明 `configSchema`，白嫖现成配置表单

三个格式插件的 manifest 加 `configSchema`（`"number"`）。
`builtin/ui-plugin-manager` 已有 schema 驱动的配置表单渲染逻辑
（先例：`workspace-panels` 的 `navigatorOpacity`），改动即落user 层 patch，
主进程 `pluginProfileStore` 负责原子写 + 备份 + 安全模式拒写。
**没有新增任何设置 UI 代码** —— 这是「复用优先」的直接收益。

## 后果与边界

- 报错文案必须报**实际生效**的阈值（`limitMessage(spec, limitBytes(spec))`），
  否则主人把上限调到 64 MiB、错误信息还写 16 MiB，会以为设置没生效。
  PureRef 旧文案「PureRef 文件超过 64MB」是硬编码的典型反例，已一并修掉。
- **非法配置一律回退默认值，绝不返回 0 / Infinity** —— 那等于替用户关掉准入闸门，
  比阈值偏小严重得多。越界值钳制而非报错（主人手滑填 99999 不该让功能崩）。
- 生效值读 `activeProfile` 而非 `pendingProfile`：导入走的是活跃插件，
  pending 可能含用户刚填但尚未重启的改动。
- 该机制只在 Windows 生效的限制无关；本 ADR 与平台无关，所有平台通用。

## 回归守卫

`scripts/check-core-foundations.cjs` 新增三条断言，防止以后写死回去：

1. **五个解析器源码里不得再出现** `MAX_(BOOK|EPUB|PALM|COMIC|PUR)_(SOURCE|FILE)_BYTES`
   —— 否则「可配置」名存实亡。
2. **每个阈值键必须出现在对应 manifest 的 `configSchema` 里** —— 否则管理面板渲染不出输入框
   （契约与 manifest 漂移）。
3. **契约数值合法性**：默认值必须落在 `[min, max]`；非法输入回退默认值；
   越界被钳制；正常值原样生效；未注入 provider 回退默认；**注入后确实读到配置值**
   （最后这条证明接线不是空转）。

另注：断言原先硬编码 `MAX_EPUB_SOURCE_BYTES = 16 * 1024 * 1024` 这类字面量，
已改为从契约读取 —— 以后调默认值不必再改测试。

## 遗留（不属于本 ADR）

`scripts/check-plugin-openings.cjs:285` 断言 `main/pluginSandboxHost.cjs` 含
`8 * 1024 * 1024`，而该文件现为 `512 * 1024 * 1024`。这是**工作区里已有的改动**
（插件沙箱 parse 上限调整）未同步更新门禁断言，与本 ADR 无关，需要时单独修。
