# ADR-045：插件作用域与事务生命周期边界

- 状态：accepted；V0/V1 实现与自动检查已验证，桌面交互待人工验收
- 日期：2026-09-23
- 关联：《插件平台V2开发规格与迁移路线》V0/V1；《插件平台V0-V1实施记录》
- 延续：ADR-001、003、005、009、030；不改变画布、持久化、资产所有权与固定 IPC

## 背景

原 loader 在根 Kernel 上注册皮肤后直接 activate；失败缺少回滚，批量重复 ID 在第二次激活后才发现，dispose 每次 reverse 且不幂等。根服务/贡献的旧 disposer 可误删后来同名登记；Set 事件订阅把不同所有者的同一回调折叠。仅靠插件自行返回 cleanup 无法管理 activate 中途抛错。

## 决策

1. **保留 Kernel 和 V1 builtin manifest。** 不替换内核、profile、项目文档版本；同步 `loadBuiltinPlugin(s)` 保持启动兼容。loader 给旧插件一个继承 Kernel 的 `ScopedPluginContext`，原 `(ctx: Kernel) => Effect | void` 继续接受它。
2. **先验证、先保留 ID，再激活。** 每个根 Kernel 独立登记 activating/active/quiescing 插件。manifest 和兼容检查、required dependencies 的 active 状态检查先于用户激活代码。批量加载按 required dependencies 排序；缺失、循环、失败 provider 的消费者不启动。同批同 ID 只取首个通过 manifest/host 校验的候选，不因首个激活失败偷偷启动第二个实现。
3. **受管激活事务。** 贡献、服务、监听暂存于作用域。插件可读自身暂存，根消费者不可见。同步 commit 不含 await；冲突时反向撤销本事务已发布与未发布资源。激活事件先缓冲（上限 1024），commit 后才发布；失败丢弃。这个事务不是数据库事务，也不回滚对已有服务的方法调用、网络请求或任意外部副作用。
4. **自动归属与可逆登记。** scoped register 可省略 pluginId；显式提供时必须与作用域相同。provide/on、effects.defer/timers 自动归属。根登记以独立身份与一次性 disposer 清理，避免旧 lease 删除新登记。多个所有者订阅同一函数得到独立 lease，取消后不再执行事件快照中的迟到回调。
5. **服务所有权。** 作用域只撤销自己提供的服务，不处置宿主已提供的服务。当前服务名仍单 provider；不引入版本目录、多 provider 绑定或动态替换。消费插件必须在 requires 声明其插件 provider；本批不自动代理所有 service 方法或发现任意缓存对象引用。宿主 provide 的文档、存储服务所有权不变。
6. **卸载策略。** 有 required dependent（含激活中、退出中）时拒绝卸载 provider；调用者先按反向依赖顺序卸载消费者。没有受管在途调用时同步 dispose 幂等清理；有在途调用必须用 disposeAsync。先 quiesce + AbortSignal，禁止新注册/emit/track，抑制监听和 timer 回调；等待 effects.track 的调用结束，默认最多 5 秒，然后反向释放资源。超时返回 `{ timedOut: true }`，不伪称工作已被强制停止。清理函数沿用同步 Effect 契约，不承诺等待任意 async disposer。
7. **异步激活独立入口。** `loadBuiltinPluginAsync` 默认 10 秒、支持外部 AbortSignal。超时/取消关闭作用域、释放 ID，迟到结果不能再次发布；迟到返回的同步 cleanup 仍执行。同步入口遇 Promise 明确拒绝，并处理迟到 cleanup/rejection。已成功加载后，激活用外部 signal 不再控制运行期；卸载走 LoadedPlugin API。
8. **管理 UI 不热卸载。** ADR-030 的 staged + reload 保持不变。renderer-materialization 仍为启动快照；上述生命周期 API 不代表当前 UI/卡片/宿主服务已经支持热替换。将来需要重新物化、消费者迁移与持久数据协议才能开放。

## 信任、兼容与后续节点策略

- scoped context 是可信同进程代码的归属/清理门面，**不是沙箱**。直接访问全局对象、直接 import 单例、持有根 Kernel、裸 setTimeout/fetch 或死循环不受此门面可靠约束；同线程死循环无法被 timeout 抢占。
- manifest `host`、`capabilities`、`resourceBudget` 的声明不代表已有 worker/main 执行宿主、权限隔离或硬配额；本轮未增加任何 IPC 权限。
- V2 manifest、版本化服务、外部包和执行宿主另批设计；不将 V1 capabilities 自动升级为权限。
- 节点持久化维持 Project Document v2。本轮不扩充任意节点类型、不删除未知节点、不迁移用户数据。后续 V4 必须先定义 schema/migration、未知节点无损保留与缺失插件降级；包卸载不等于资产/文档删除。
- 既有 durable import journal、staging、derivative worker 与 repository 保持唯一所有者；effects.track 仅是 scope 的 Promise 在途集合，不是另一套任务调度器/数据库。
- ADR-037/FDD-037 历史文字中的外部安装/真实生成能力不能当本批证据；当前 builtin provider 中仍有示例产物和日志占位，外部宿主与真实端到端生成必须由后续阶段实测。

## 验证与后果

新增 lifecycle 行为检查纳入 `npm run check`；初始 11 组在旧实现上全部失败，修复后通过，再扩充到 15 组；旧 foundation/架构保护未修改。21 个真实 builtin 全量装载并反向清理通过；arrange-tools 4 条命令迁移为自动归属。完整 typecheck/build/foundations/SSR/性能契约检查通过。详细证据、未测项与备份路径见实施记录。
