# ADR-034：画布自动保存与启动恢复边界

- 状态：verified
- 日期：2026-09-22
- 轮次：R34 / Phase UX7 (REQ-001)
- 关联：`FDD-034-PhaseUX7-画布自动保存与启动恢复.md`

## 背景

在 R1–R33 之后，Artflow 的持久化后端（Project Document v2、SQLite 资产库元数据、内容寻址 blob 仓及 R18–R23 工作区变更感知）已全部就绪。
但此前缺乏自动持久化和启动恢复机制：
1. 用户的画布编辑在未手动点击保存或按 Ctrl+S 的情况下，直接关闭应用会导致最新编辑丢失。
2. 重启 Electron 应用后，由于主进程控制器未记录上次打开项目，`getStatus()` 返回未打开，用户必须手动再次选择项目文件夹。

《需求文档.md》中的 REQ-001 明确提出了“画布自动保存 + 启动自动恢复”的高优先级要求。

## 决策

1. **会话持久化与启动恢复边界**：
   - 主进程 `ProjectStorageController` 增加可选 `sessionFilePath`。在成功打开项目时记录 `lastProjectRoot`，并在 Electron `app.whenReady()` 阶段通过 `restoreLastSession()` 自动恢复上次打开的项目仓库。
   - 若上次项目目录不存在或失效，控制器自动清除该无效会话并平稳回退至未打开状态，绝不阻塞应用启动或抛出未捕获异常。
   - 渲染进程 `useFileSystem` 暴露 `restoreStartupProject()`。在应用挂载时探测 `getStatus()`，若已打开则自动加载项目文档并调用 `loadBoardData()` 恢复画布，建立项目基线状态，通知栏显示“Workspace restored.”。

2. **自动保存防抖与非阻塞执行**：
   - 仅在桌面受管存储（`isManagedProjectStorageAvailable`）且当前项目已打开时启用自动保存；浏览器端环境严格保持手动保存，不破坏既有 File System Access API / 导出逻辑。
   - 当检测到未保存变更（`hasUnsavedChanges`）时，启动 1500ms（`AUTOSAVE_DEBOUNCE_MS`）防抖计时器；用户连续编辑时重置防抖计时器，避免高频全量或逐帧写入。
   - 自动保存复用 `saveProject(boardsAtSaveStart)` 路径，在后台异步完成，不弹窗、不挂载遮罩加载动画（`isLoading` 保持 false），仅在工作区活动栏显示轻量提示。
   - 保存成功后原子更新 `projectChangeState` 基线；若保存中途产生新编辑，保留 dirty 状态并顺延下一轮保存。
   - 监听窗口 `beforeunload` 事件，在未保存且非正在保存状态下触发优雅冲刷保存。

3. **安全与能力隔离**：
   - fixed preload/main capability 保持为 **13**，不新增 IPC 频道、不开放任意文件路径访问。
   - 手动 Ctrl+S 及手动保存按钮逻辑完全保留且优先权不受影响。

## 验证结果

- `typecheck`、`build`、`check:foundations` 全部通过（exit 0）。
- `runAutoSyncChecks` 验证了：
  - `canScheduleAutoSave` 纯条件谓词在各类状态组合下的正确性；
  - 会话载荷解析与容错机制；
  - `ProjectStorageController` 会话记录、重启恢复、路径失效自愈与关闭流程；
  - `useFileSystem` 与 `App.tsx` 关键路径的源码接线一致性。
- Preload/Main 通道数保持严格为 13。

## 边界与不可重复项

- 本轮仅实现当前单项目的会话持久化与启动自动恢复；多窗口多项目标签页管理仍属未来规划。
- 自动保存通过现有 v2 受管保存管道完成，不在此越权设计复杂的跨进程分布式事务锁。
