# ADR-020：画布导航器本地相机与有界概览边界

- **状态**：accepted（已验证）
- **日期**：2026-09-22
- **关联**：ADR-001、ADR-011、ADR-018、ADR-019

## Context

MainCanvas 已以 renderer-local `panOffset` / `zoom` 维护实时视图，R11 local index 是其 live culling authority；R12/R13 只查询已保存 snapshot，不能被误用为 live minimap。用户需要一个明显的空间导航 UI，但一个无界、full-thumbnail minimap 会在大画布重新引入 SVG/DOM 压力，并可能把 live state 错接到 persistence IPC。

## Decision

1. `CanvasNavigator` 仅是 renderer-local overlay，读取 App 的 current `elements`、`panOffset`、`zoom` 和主 SVG size；它不读 repository，也不调用 bridge。
2. Overview geometry 使用 MainCanvas 既有 affine transform 的反向公式；click 只将 world point re-center 到同一 Board 的当前 zoom。
3. `Fit canvas` 使用 finite content AABB，并复用 existing 0.1–10 zoom range；它用 `updateActiveBoard` 更新 existing camera fields，不创建 Element operation。
4. Overview render budget 固定为 240 markers。frame markers 优先，其他 source-order evenly sample；all finite content 仍参与 union/fit。
5. 为避免 `getElementBounds` 对 nested/cyclic group child traversal，group 只使用 persisted renderer rect；其 children 独立贡献 bounds。非-group 继续使用 existing bounds helper。
6. Navigator 在 presentation mode 隐藏；它不是 saved view、multi-board navigator、thumbnail renderer 或 R11/R12/R13 consumer。

## Consequences

- 用户得到显著可见、可点击的 canvas navigation UI，且不需等待 storage/Worker 路线。
- Camera move 仍是 current Board state；项目保存仅沿用既有 save path，不产生新 persistence semantics。
- 240 cap 保障 overlay DOM work 有上限，但不会影响 Fit 内容范围；UI 必须诚实展示 sample 状态。
- 未来如果需要 viewport-rectangle drag 或 thousands-of-markers density render，必须走 Worker/tile/Hybrid 设计，而不能悄悄提高 cap。

## Rejected alternatives

- **消费 R12/R13 SQLite query**：它代表 saved snapshot，无法正确反映 unsaved renderer state。
- **为每张卡生成 thumbnail / foreignObject minimap**：会复制既有 SVG/DOM scalability problem，超出本轮。
- **无限 marker SVG list**：对大项目没有预算保护。
- **把 navigator position 单独持久化或做 recent views**：现有 Board pan/zoom 已是唯一 camera state；新 persistence 无必要。
