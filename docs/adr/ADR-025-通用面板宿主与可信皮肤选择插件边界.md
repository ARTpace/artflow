# ADR-025：通用面板宿主与可信皮肤选择插件边界

- **状态**：accepted（verified）
- **日期**：2026-09-22
- **关联**：插件系统设计 §1/§3/§8、ADR-007 / FDD-007、FDD-025

## Context

`ui_panels` 已在 Kernel SLOTS 中保留，skins 已作为 data contribution 被 SkinEngine 消费，但没有泛化 React panel host。把 theme selector 写入 App 或 existing CanvasSettings 会让本体持有具体 skin business，违反“内核零业务逻辑 / UI 走贡献通道”。同时 builtin React component contribution 只能在 trusted renderer context 中运行，不能提前把此机制误表述为 third-party UI sandbox。

## Decision

1. 建立 `plugins/panel-contributions.ts` 和 `plugins/panel-host.tsx`：前者定义 typed panel contribution/list projection，后者只渲染 generic catalog、selected panel、back/close/Escape/empty state。它消费 `kernel.contributions.list('ui_panels')`，不识别任何具体 plugin id。
2. Panel component 接收 `{ kernel, onClose }`。这使插件经 Kernel service boundary 协作，而非直接 import sibling plugin；SkinEngine 以 `SKIN_ENGINE_SERVICE` 在 React mount 前提供。
3. `builtin/ui-skin-picker` 作为第一个 `ui.panel` builtin：manifest declarative identity/capability/required skins dependency；activation 注册 namespaced contribution；其 React component 只读取 SkinEngine service 并调用 `setSkin`。
4. App/TopBar 只拥有 generic Extensions trigger 与 host open state，绝不出现 `skin-picker` id、skin names、token colors 或 switch logic。active skin 在本轮不保存，避免越过 P2 config center / P4 profile patch ownership。

## Verification

- 2026-09-22 remote `typecheck`、`check:foundations` and production full `check` all exited 0.
- Foundation verifies ordered/disposable `ui_panels`, mediated SkinEngine service, preview/apply behavior, manifest/profile seam, and that App/TopBar/host remain generic rather than skin-specific.
- Closing remote read-back matched the R25 source and governance/plugin-document set exactly.

## Consequences

- 用户得到可发现的 Theme library，已有 default/paper skin 真正可用。
- 新面板可复用同一 host，并通过 existing disposer/profile lifecycle 变得可逆。
- Component contribution 的 host API 形成明确 trusted-builtin boundary；external/restricted plugin 仍不能使用它。
- Panel persistence、layout/docking、commands 和旧硬编码面板迁移保持后续决策，不在本轮隐式引入。

## Rejected alternatives

- **将 skin picker 加进 CanvasSettings appearance tab**：快捷，但继续将插件业务硬编码进本体。
- **把 skin picker 的 React component 放入 manifest JSON**：JSON 不能安全表达 executable component；builtin activation registration 是现有受信通道。
- **直接 import SkinEngine singleton / sibling builtin**：绕过 service contract，未来插件隔离无法成立。
- **现在就持久化 active skin 到 localStorage/profile patch**：会抢占 P2 config center/P4 patch 的 ownership。

## Revisit triggers

External/restricted UI plugin、panel docking/layout persistence、config UI、commands/ui_toolbar、legacy panel migration、runtime profile reload 或 panel cross-window behavior 必须新建 FDD/ADR。
