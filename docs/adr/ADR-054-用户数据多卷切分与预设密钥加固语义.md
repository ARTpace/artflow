# ADR-054 · 用户数据多卷切分、工作区布局与预设/密钥加固语义

- 状态：已采纳
- 日期：2026-10-09
- 关联：`docs/用户数据层架构方案.md` §4 P3、ADR-053（安全模式）

## 背景

P1 建了「主进程文件持有用户数据」的地基，P2 把渲染层 `localStorage` 里的存量键全部收敛到
`config/preferences.json` + `config/secrets.json`。P3-① 补上了安全模式（工厂启动）。

剩下的五项都是"Blender 有而我们没有"的桌面化能力：工作区布局持久化、最近工程列表、
设置预设导出导入、存储管理面板、密钥加固。它们的共同点是**引入新的存储面**，
因此必须先定清楚"什么放哪个卷、谁有权写、坏了怎么办"。

## 决策

### 1. 卷按「写入频率 + 敏感度」切分，而非按功能切分

```
userData/config/
├─ preferences.json   全局偏好（小、低频：语言/画布/输入/外观选择）
├─ workspace.json     工作区布局（中频：拖一次面板写一次）
├─ recent-files.json  最近工程（低频小值，但整表替换）
├─ secrets.json       密钥（敏感：独立文件 + 权限收紧 + OS 钥匙串加密）
└─ presets/           设置预设导出（用户可分享的文件）
```

单文件卷每次写入都要重写整篇，所以**高频写不能与低频值混在一个文件里** ——
否则拖一次面板就顺带重写一遍全部偏好。同理，密钥独立成卷是安全边界，不是分类习惯。

所有卷共用同一个 `main/configStore.cjs`，并**统一注入安全模式**（读空 + 拒写）。
存储层自己不读环境变量 —— 回归脚本因此能直接传 `safeMode: true` 做对拍。

### 2. 工作区布局：只在值真的变化时写

`hooks/useWorkspaceLayout.ts` 维护"**上次已提交的值**"，只有与它不同才落盘。两个坑：

- 无条件写 → 从没动过布局的用户也会在磁盘上留下一整套默认值，
  「用户真选过的布局」与「默认值」从此分不开（而且 React StrictMode 会把 effect 跑两遍）。
- 用「首次渲染的值」当基线 → 用户**改回原值**时反而漏写（内存 false、磁盘 true）。

「上次已提交的值」两个坑都没有。

布局键集中在 `plugins/workspace-layout.ts` 的 `WORKSPACE_KEYS`，读回来的值一律当
**不可信输入**校验（用户能手改 JSON），失效值回落到默认 —— 与设置页"分组失效则回落第一项"配合，
避免"打开了设置却是空白页"。

只收录**常驻面板**（侧栏 / 工程 / 书签 / 查找 / 画板）。命令面板、右键菜单、标签编辑器
这类"交互中才存在"的浮层刻意不入卷：重启后自动弹出一个命令面板不是记住布局，是干扰。

### 3. 最近工程由主进程记录

路径是主进程 `dialog` 选出来的，渲染层只拿到 `projectName`。让渲染层记录就得把绝对路径
回传一次（多一处可能不一致）。打开与保存都记 —— 两种动作都意味着"这个工程我还要用"。

去重按 **Windows 路径大小写不敏感**（`D:\Foo` 与 `d:\foo` 是同一个工程），
并**标记**（而不是过滤）磁盘上已不存在的目录：这类条目在界面上**灰掉而不是隐藏**（带 `missing` 标记）——
直接消失会让用户以为"我的工程不见了"。

### 4. 预设只收录 preferences + workspace

`PRESET_VOLUMES` 是**刻意的安全边界**，不是遗漏：

- `secrets`：预设的用途是分享/迁移一套调好的配置，把密钥带进去等于泄漏；
- `recent-files`：本机路径清单，导到另一台机器上全是死链。

预设文件自描述（`kind: "artflow.preset"`），名称过白名单正则（**不接受路径分隔符**，
从根上排除路径穿越），单文件 2MB 上限。

**导入后不假装即时生效**：语言、外观、皮肤都住在各自的模块级单例里，改文件不会让它们
重新求值。与其做成"一半悄悄生效"的迷惑状态，不如明说"重启后生效"
并给一个一键重启（`window.artflowApp.restartApp()`）。

### 5. 密钥加固：值级加密 + 前缀自描述 + 解不开不丢

`main/secretCodec.cjs` 把 `safeStorage`（OS 钥匙串）挂在 `configStore` 新增的
`valueCodec` 钩子上：

- **值级**而非整文件级：整篇加密会让 `stats()` 连键名都数不出来，
  而"存储管理面板"恰恰要展示键数与字节数。
- **带前缀自描述**（`enc:v1:`）：没有前缀 = 明文 —— P1/P2 写下的旧 `secrets.json`
  天然被读取（零迁移），首次写入时自动升级为密文；将来换算法写 `enc:v2:` 即可。
- **钥匙串不可用时拒绝写入**，绝不静默降级写明文。用户以为被加密了、实际没有，是最坏的结局。
  代价是"钥匙串坏掉时存不进新密钥"—— 这是**诚实**的失败，而不是偷偷降低安全性。
- **解不开的值不许丢**：`decode` 失败时该键从 `values` 移除（渲染层不该看到密文），
  但原文被记进 `preserved`，写回时**原样并回**。否则用户一次普通保存就把密钥从文件里抹掉了。
  典型成因：系统钥匙串被重置 / 换机。
- `restrictPermissions`：写入后 `chmod 0600`。POSIX 上有效；Windows 上近乎 no-op ——
  那边靠的是 DPAPI 加密，不是 ACL，这一点写在注释里以免后来者误以为漏了。

### 6. 存储面板与"清空缓存"的边界

面板只读，回答"数据在哪、多大、坏没坏"三个问题。唯一的动作是清空缓存，
**严格限定 `userData/temp`**，且主进程侧有一道路径守卫（`basename` 必须是 `temp`
且确实在 `userData` 之下）—— 这个函数执行删除，任何一次路径算错都是不可逆的数据损失。

预设覆盖范围在面板上逐卷标出（`inPreset`），避免用户误以为"导出预设 = 备份全部"。

## 后果

- 新增一个卷的成本降到"`createConfigStore` 一行 + `configStores` 白名单一行"，
  渲染层用 `createConfigVolume(name)` 一行接入。
- 通道面刻意保持**少而通用**：`config:read-sync / write-sync / stats-sync`（`payload.store` 选卷）
  + `config:presets` / `config:storage`（`payload.op` 多路复用）。
  新增这三条 storage 通道会触发 `check:foundations` / `check:asset-inventory` 的
  "通道数量"护栏，**必须同步更新计数** —— 这道护栏正是用来逼出"新通道有没有配齐
  main + preload 两侧"的：本轮就靠它抓到了 preload 漏定义三个通道常量（引用到 `undefined`）。
- Windows 上 `safeStorage` 加密后，密钥文件被复制到另一台机器将无法解密
  （`preserved` 保证不丢，但用户需要重填）。
