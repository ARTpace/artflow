# ADR-048：声明式扩展包、受管导入与守卫工具链

日期：2026-09-23。状态：实现与自动检查/独立浏览器验证通过，Electron 真机端到端与 V8 性能回归待验。检查结论见《插件平台V3-V7扩展实施记录》。延续 ADR-045/046/047。

## 决策

1. 外部扩展以**数据-only 声明式包**落地（`manifestVersion: 2`、`engine: declarative-v1`）。包体不含入口、URL、脚本或二进制字段；校验器对未知字段、越权 ID、重复/缺失字段、超尺寸（包 ≤64K、数据 ≤16K/事务）直接拒收。本阶段不执行外部 JavaScript——这是能力边界，不是实现疏漏；真实脚本宿主、CSP 与 worker 进程隔离属于后续阶段。
2. 安装/启用状态存于 localStorage 单一清单（`artflow.extensions.v2`，≤16 包）。依赖必须已安装且启用；停用/卸载被依赖方被拒绝；运行时注册表由清单同步，UI 经订阅观察。包内权限（`document.read/write`、`imports.parse`、`agent.invoke`）显式声明，版本替换时已授权取交集（只减不增）并保留 `previous` 供诊断。
3. 导入闭环复用既有单一状态所有者：文件按已安装包格式匹配 → 受管批次（≤64 文件、≤1000 记录/批，一批=一个文档事务）→ 真实后台 Worker 解析（≤2 MiB、分块读取、30s 超时、AbortSignal 取消并终止 Worker）→ `extension.node.create` 提交（requestId 幂等、revision 冲突拒绝）。解析失败只标记对应文件条目；提交失败不产生部分节点。不新增第二套 jobs 队列，面板只做观察与取消。
4. 节点 schema 由包内 `node` 声明（字段类型/默认值/默认几何/迁移链）。SDK 新增 `extension.node.create` / `extension.node.update`：未知或停用的类型返回 NOT_FOUND，绝不凭空创建；数据字段按 schema 类型校验，未知/伪造字段拒绝；存储版本落后于当前包版本时在首次触碰时惰性执行迁移链（缺失迁移或字段冲突则拒绝并保留原数据），版本超前同样拒绝且保留数据。
5. 持久化不改 v2 算法：扩展节点字段经既有 `properties` 通道往返，核心序列化器对未知 nodeType 本就通用。插件缺失/停用时卡片降级为占位卡，节点数据完整保留；重新安装/启用后无需迁移即恢复。
6. 操作链分四阶段：before（通知/前置）→ guard（最终拒绝，纯判定）→ wrap（可嵌套包装）→ execute → after（观察）。guard 的拒绝不可被后续包装器覆盖；execute 前再执行一次 authorize，执行中包被停用/降级授权立即中止；全程受超时与外部 AbortSignal 约束。actor 永远来自可信 scope，不接受请求自报。
7. 扩展工具按参数投影为命令与 Agent 工具：参数按 schema 类型校验（未知/缺参/非有限数拒绝）；命令在扩展停用后从注册表移除；Agent 投影仅包含启用且具 `agent.invoke` 授权的工具。既有工具名危险词正则保留，但不再是唯一防线。
8. 宿主侧新增 `builtin.core-extensions`（通用消费面）与 `platform.extension-runtime` 服务：安装管理 UI、守卫钩子、命令投影都注册在该插件下，随其生命周期清理。App 只做三处通用接线（SDK schema 提供器、文件路由回调、两个通用面板），没有任何样例特判、switch case 或静态 import；样例 `extensions/sample-inspector/` 位于源码树外，经设置区安装。
9. CanvasElement 的 default 分支对 `ext.*` 节点使用通用 schema 卡片（foreignObject + 冻结样式），不引入每扩展组件；选中扩展节点时显示 schema 驱动的属性面板（改动经 SDK 事务提交，可撤销）。
10. 本批维持可信同进程边界：不是恶意代码沙箱。固定受限 IPC、资产所有权、staged+reload 设置、项目文档 v2 与既有性能保护均未改动；无新增 npm 依赖。

## 范围

本批实现规格 V3（受管导入闭环）、V4（声明式节点 schema/迁移/占位）、V5（四阶段守卫链与带参数工具投影）、V6（数据-only 外部包宿主与管理面）、V7（同 ID 版本替换契约）。**未完成**：V8 端到端真机/性能回归、真实脚本包宿主与 CSP/worker 进程隔离、核心服务目录的第三方 provider 热替换（仍仅 core provider 启动绑定）、大文档与 5000 节点级压力测试。

## 备选与否决

- **直接执行外部 JS 包**：否决。当前宿主无进程/worker 隔离与 CSP 边界，执行外部脚本会把同进程可信假设放大为安全假设。数据-only 形态先打通"安装→解析→节点→工具"全链，脚本宿主单独立项。
- **为样例插件新增 App 特判/核心 switch**：否决。规格 §3.3 明确要求 diff 不得包含样例特判；通用 schema 卡片/面板/路由满足同一目标且对任意声明式包成立。
- **为扩展导入另建 jobs 队列**：否决。导入规格要求单一状态/队列所有者；批次状态机挂在运行时上，提交仍走文档 SDK 事务，避免双所有者竞态。
- **在启动时为所有安装包预注册卡片组件**：否决。扩展可在运行中安装/停用，卡片可用性必须是活查询（订阅 + 版本快照），与 renderer materialization 的启动固化快照区分。
