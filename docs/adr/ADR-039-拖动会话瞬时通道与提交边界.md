# ADR-039：拖动会话瞬时通道与提交边界

- **状态**：accepted（代码与自检已完成，实际拖动手感与回归矩阵待主人真机确认）
- **日期**：2026-09-23
- **关联**：ADR-011、ADR-014、ADR-017、ADR-020、ADR-023、ADR-038；设计见《画布交互性能优化实施计划.md》P1-B

## Context

ADR-038（P1-B'）把相机（pan/zoom）从顶层 `boards` 里剥了出来，但**元素拖动**仍然逐帧写文档：

```ts
// 旧路径（hooks/useCanvasInteractions.ts 的 dragElements 分支）
setElements(prev => prev.map(el => movingIds.has(el.id) ? { ...el, x: startPos.x + finalDx, ... } : el), false);
```

`setElements` 写的是 `Board.elements`，也就是文档状态。于是拖动一张卡片的代价是：

- App 整棵函数体重跑（`boards` 变了）→ TopBar / Toolbar / PromptBar / 侧栏 / 插件 widget 宿主全部重绘。
- `MainCanvas` 内的 `viewportIndex` 每帧重建、`visibleElements` 每帧重算，`isElementVisible` 与每个兄弟元素的 memo 比较全部重跑一遍。
- 每帧产生一条**新的数组 + 新元素对象**，`SVGDefs` 的 defs 每帧重建。
- 拖动期间项目一直被标记为"有未保存改动"（`pendingBaseElementsRef` 每帧记一次起点）。
- 顺带污染撤销基线：`pendingBaseElementsRef` 在拖动期间被反复写入。

代价与"整个工作区的规模"成正比，而拖动实际只改了 N 个元素的两个数字。P1-B' 已经把共享基建（瞬时通道 + 手势结束单次提交 + imperative 呈现）做出来了，本批把"拖动对象"这一半接上。

与相机不同的是，拖动还牵着三条业务语义，不能只看性能：

1. **吸附**（对齐参考线 + 网格兜底）必须在会话内继续工作；
2. **Frame 父级归属**要在松手时按元素**新位置**重新解析（跨 Frame 拖入拖出）；
3. **撤销**必须只产生一条记录，且基线是拖动前的状态。

## Decision

1. 新增 `utils/drag-session-store.ts`：拖动会话的瞬时通道，与 Board 文档状态解耦。
   - 快照 = `{ elementIds, offset, guides }`。**会话内 id 集合引用保持稳定**（订阅者把它当 `useMemo` 依赖），数值不变时返回同一快照引用（`useSyncExternalStore` 不能自激）。
   - `begin()` **刻意不通知订阅者**：会话起点的位移是 0，等同静态呈现，此时通知只会在 mousedown 瞬间白重绘一次。
   - 参考线作为会话的一部分（`setGuides` 按内容去重）——它唯一的消费者 `CanvasOverlays` 就在 `MainCanvas` 内，走通道后拖动路径上 App **零 setState**。
   - `end()` 返回最终 `{ elementIds, offset }` 并复位预览；**零位移也返回会话**（点一下落在 Frame 内的元素需要走父级解析，这是既有行为）。`cancel()` 只复位（切画板 / 卸载）。
2. 新增 `utils/drag-offset.ts`：
   - `applyDragOffset(element, dx, dy)`：一次位移作用到元素上的**唯一实现**。`path`/`arrow`/`line` 的位置存在 `points` 里而不是 `x/y` 里，预览与提交分成两处实现的话，点集元素会在松手瞬间跳位置。位移为 0 时返回原引用。
   - `applyDragPreview(elements, ids, offset)`：只替换会话内元素、其余保持原引用——这是 `CanvasElement` memo（按 `element` 引用比较）能只重绘被拖动元素的前提。
3. 新增 `utils/drag-commit.ts`：`applyDragCommit(elements, session, snapshot)` 是会话落地的唯一入口。
   - 先整体应用位移，再在**位移后的列表**上解析父级。拿拖动前的位置判断"落在哪个 Frame 里"，跨 Frame 拖入会完全失效。
   - Frame 自身不参与父级解析（Frame 不能嵌套 Frame），但位置照样位移。
4. `MainCanvas` 呈现层：`presentElements`（全量，供 group 递归求包围盒）与 `visiblePresentElements`（渲染用）都由 `applyDragPreview` 得到；`SelectionHandles`、`ToolbarOverlay`、**`SVGDefs`** 一并接呈现层。
5. 裁剪白名单 = 选中集 ∪ 拖动集。拖动期间元素的新位置只存在于通道里，视口索引仍是拖动前的位置——只按选中集放行的话，被拖动的 Frame/Group 的后代一离开视口就会被裁掉。
6. 鼠标松开时为提交点：`flush` 最后一帧样本 → `end()` → 一次 `commitAction`（位移 + 父级，一条撤销记录）。**候选索引显式传 null**：拖动期间位置没有写回文档，R14 快照指向拖动前的位置，用它窄化候选会漏掉新位置附近的 Frame。非拖动路径（resize/rotate/lasso 等）仍按原样使用保守索引。
7. `SVGDefs` 的 memo 比较从"数组引用变了就重绘"改为**按圆角图片的几何比较**（新增可测的 `hasSameRoundedImageGeometry`）。clipPath 是绝对坐标：拖动圆角图片时裁剪区留在原地会把图片裁没；反过来，拖一张非圆角图片不该重建整个 defs 子树。
8. 无 `dragSessionStore` 时，旧的逐帧 `setElements` 路径**原样保留**（向后兼容 + 按文件回滚）。

## Consequences

- 拖动期间：`boards` 不变、App 外壳不重绘、viewport 索引不重建、撤销基线不被污染、项目不被标脏；面板与媒体子树不再参与拖动。
- 拖动中 `App` 的唯一重绘来源是会话内的一次性状态（`isInteracting`）与 `commitAction`，其余全部发生在 `MainCanvas` 内部。
- **已知降级**（有意接受，见 Revisit triggers）：
  1. `CanvasNavigator` 小地图在拖动中不跟手（它在 App 层，读文档 elements），松手后跳到新位置；
  2. `GalaxyStarLayer` 的星点在拖动中不跟手（极远景 LOD0，拖动场景少）；
  3. 侧栏属性面板里的 x/y 在拖动中不刷新，松手后更新（拖动中刷新等于让 App 参与每帧）。
- **未扩大既有 gap**：手势只有 `mouseup` / `mouseleave` 两条结束路径，没有 `pointercancel` 与 Esc 兜底；拖动中丢失 mouseup 时，改动前后都会残留交互模式（改动前残留的是脏文档，改动后残留的是未提交的预览）。本批不重构手势生命周期。
- 拖动提交时父级解析放弃候选索引、回退一次全量扫描（O(N)，仅在松手时一次），换取跨 Frame 归属的正确性。

## Rejected alternatives

1. **给被拖动元素外层套 `<g>` 做 imperative transform。**
   元素在 SVG 里是扁平渲染的，但 Frame 的裁剪与 z-order 依赖真实层级；把所有拖动元素提到临时层会改变层叠与裁剪。而且选区手柄、元素工具条仍必须走 React，改完两套机制并存。
2. **保留索引窄化，改用"位置偏移的快照"（查询时把 region 反向平移）。**
   数学上可行，但要扩 `interaction-spatial-query` 的公共接口，并且 R14 的边界明确禁止消费者发布/篡改 `MainCanvas` 拥有的快照。收益只是一次 O(N) 扫描，不值这个接口代价。
3. **拖动中继续写文档，但把消费方都 memo 掉。**
   `boards` 的所有者是 App，`setElements` 必然重渲整棵树；要把每个消费方都隔离，等于把整个 App 重构成订阅制，风险远大于收益。
4. **把 `alignmentGuides` 留在 App 的 state 里，只做"内容不变就不 setState"的去重。**
   §2 采用了通道，但保留了这个去重作为无 store 时的回退。只去重不做通道的话，吸附跨过阈值时仍会逐次拉起 App 整棵树。
5. **顺手重构手势结束（pointercancel / Esc / window 级 pointerup）。**
   收益是修一个既有的、与本批无关的 gap；与本批的"拖动不再写文档"耦合度低，混在一起会让回归面无法归因。

## Revisit triggers

- 真机上拖动时若发现"元素跟手但松手位置与视觉位置不一致"，优先检查 `applyDragPreview` 与 `applyDragCommit` 是否被分叉成两份实现（自检里有几何一致性断言）。
- 拖动中若发现圆角图片缺一块/整张不可见，检查 `SVGDefs` 是否被改回"数组引用变就重绘"。
- 拖动中被拖元素一离开视口就消失，检查裁剪白名单是否漏掉拖动集。
- 若真机确认"拖动中侧栏数值不刷新"或"小地图不跟手"不可接受：小地图/属性面板改为订阅拖动通道，而不是让它们回到 App 的每帧重渲。
- `ToolbarOverlay` 在拖动中每帧重渲（它没有 memo）若被实测证明是瓶颈，改为只订阅"选中元素呈现矩形"。
- 需要 `pointercancel` / Esc 兜底时，作为独立小批次做，并为"会话未提交"补充明确的取消语义。
