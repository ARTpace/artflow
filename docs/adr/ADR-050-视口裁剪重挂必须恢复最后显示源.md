# ADR-050：视口裁剪重挂必须恢复最后显示源

- 状态：已采纳（2026-09-23，P1-H 后续修复）
- 相关：ADR-044（选中状态不得影响渲染驻留——本问题的引入点）、ADR-049（相机合成层与中档纹理预算——prepared 换源 hook 的引入点）
- 上游文档：`docs/实施迭代台账.md`
- 自检：`scripts/check-image-preparation.cjs`（行为 + 源码契约）、可选真机夹具 `scripts/check-image-preparation.browser.cjs`

## 背景

P1-H 把"选中集"从裁剪白名单移出（正确修复"全选绕过裁剪"），副作用是：滚动/缩放时
视口边缘元素开始**真实卸载/重挂**——之前"导入即全选"让所有元素都驻留在白名单里，
重挂路径从未被大规模触发。

重挂后 `usePreparedImageSource` 的初始 state 一律是 fallback：

- 有缩略图的元素：先画缩略图，等预解码队列交付 medium/standard 后换 href
  → 视口边缘随滚动"闪一次低清再变清晰"；
- **没有缩略图的元素：fallback 是完整 `element.href`**，重挂等于一次全新加载解码
  → 屏幕上表现为"图片消失"，解码完才回来。

两者叠加，正是真机反馈的"滚动缩放会闪、图片会消失"。

已排除的候选：滚轮手势不置 `isInteracting`（`useCanvasInteractions.ts` 滚轮入口明确注释），
排除 medium↔standard 换档振荡；prepared 队列"保留旧图直到新源解码完"语义自洽，
排除换 href 空窗；transform 无双写。

## 决策

`usePreparedImageSource` 增加模块级"最后显示源"记忆（`rememberLastDisplayedSource`
/ `peekLastDisplayedSource`）：

1. **重挂从"上次实际显示的源"开始**，不再从 fallback 开始——视觉上等同从未卸载。
   像素命中依赖浏览器图片缓存（刚显示过的 URL 几乎必然还在）与预解码队列，
   记忆本身只存 src 字符串与档位，**不持有解码资源**。
2. **资产身份校验**：记忆按 `elementId` 存、读时校验 `baseSrc` 一致；资产被替换后
   旧记忆作废，绝不把旧资产的像素交给新资产（延续 hook 既有契约）。
3. **容量有界**（2048 条，Map 插入序即 LRU 序）：元素删除后残留条目自动被淘汰，
   不做逐条清理以免引入新的生命周期耦合。
4. 成功提交（`result.ok`）时写回记忆；解码失败路径不写（保留的仍是旧源，
   下次提交自然会覆盖）。
5. 记忆命中的首次渲染里 `desired.src === displayed.src`，effect 提前返回
   → 重挂**不会**重新提交同一请求（真机夹具断言了这一点）。

刻意的非目标：不增大 overscan（150 屏幕像素足够覆盖发布滞后）、不改裁剪白名单
（ADR-044 的结论不变）、不给档位加滞回（ADR-043 的教训：memo 看不见的历史状态必然错位）。

## 后果

- 视口边缘的重挂不再可见：无闪烁、无空窗；裁剪的挂载量收益完整保留。
- 已知边界：若一个 URL 在卸载期间被浏览器图片缓存驱逐（极端内存压力），
  重挂仍需一次真实加载——这是无状态裁剪的理论下界，兜底是预解码队列的
  cacheHit 通道。
- 卸载会释放原图 LRU 准入（`useImageLOD` 的既有行为），重挂后重新排队准入
  （180ms 批处理）——期间显示 standard，属可接受的短暂降级。

## 反证（确认断言不是假绿）

| 反证 | 结果 |
|---|---|
| 删除 hook 初始化里的 `peekLastDisplayedSource` | `check-image-preparation` 源码契约断言失败 |
| 删除成功提交里的 `rememberLastDisplayedSource` | 同上（hook 源码契约） |
| `peek` 去掉 `baseSrc` 校验 | 断言失败（资产替换用例） |
| 容量守卫移除 | 断言失败（洪泛用例，最旧条目必须被淘汰） |
| 真机夹具：重挂后同步 href ≠ standard | `check-image-preparation.browser.cjs` remount 用例失败 |
