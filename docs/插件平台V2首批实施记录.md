# 插件平台 V2 首批实施记录：文档几何与原子操作 SDK

日期：2026-09-23　｜　阶段：V2 最小闭环，不是完整插件平台　｜　ADR-046

## 1. 已实现

- `canvas.document@1`：当前 session/画板/revision、只读几何投影、有界分页、节点 ID 过滤、文档变更订阅。返回对象与嵌套几何深冻结且脱离内部对象，不暴露资产 locator、完整 Element 或 setter。
- `canvas.operations@1`：`node.patchGeometry` 原子批次、结构化结果、session/board/revision 检查、requestId 去重、锁定节点/非法字段/活动交互保护。
- 一个批次复用 `commitCanvasOperation` 产生一条既有撤销记录；noop 不写历史，任一操作失败全批不提交。
- profile 增加显式 serviceBindings；启动目录记录服务 major/provider/available，拒绝未知绑定、错误 major 和重复 provider。当前只接入 `core.canvas-document`，不支持外部 provider 或热替换。现有 localStorage 用户层仍只保存 patches；本批没有新增绑定编辑 UI。
- `builtin.arrange-tools` 的水平/垂直分布、随机排列、等面积归一共 4 条命令改用 SDK，不再调用 App 专属 mutation/export 业务函数。操作 actor 从 loader-created scope 注入，请求不得自报 actor。
- provider cleanup 和插件 AbortSignal 共同使旧 facade 失效；订阅自动取消。

## 2. 核心接线及审计结论

### 单一状态，不是双文档/双历史

原 Board[] / activeBoardId 由 useCanvasState 内 React state 持有。为保证同一事件循环内的提交和 revision 判断准确，本批将这两个值移入 `utils/canvas-document-state.ts` 的一个同步所有者，React 用 `useSyncExternalStore` 订阅。没有另建插件专属文档副本；既有 setBoards/setElements/undo/redo 都消费同一份状态。

历史算法仍是 `utils/operationHistory.ts`，文档保存仍是 `utils/projectDocument.ts`。二者未修改。session 在真实 loadBoardData 成功加载项目时更新；rev 根据 immutable elements 引用及历史游标变化推进。camera-only 更新不推进节点 revision；删除/重建同 ID 画板不能复活旧 token。

App 只新增通用目录/provider 接线与选择、busy 状态适配，没有为排列插件 ID 或新节点类型增加特判。SDK 在 drag-session 或旧 pending interaction 时拒绝写入，避免混入未提交的手势历史。

### 旧服务风险未被掩盖

审计发现原 App 的 legacy mutation/export/view 服务先注册 ref.current，后续 render 替换 ref.current，Kernel 中旧对象可能继续持有初始闭包。新 SDK 不复用这一对象生命周期。其他旧插件仍使用兼容服务，本批没有顺便迁移所有插件，也不宣称这个历史问题已经全局修复；后续应单独做稳定代理与跨画板回归测试。

## 3. 最小公共契约

```ts
const document = usePluginService<DocumentService>(ctx, 'canvas.document', 1);
const operations = usePluginService<OperationsService>(ctx, 'canvas.operations', 1);
const token = document.getContext();
const nodes = document.query(token, { offset: 0, limit: 100 });
const result = operations.apply({
  sessionId: token.sessionId,
  boardId: token.boardId,
  revision: token.revision,
  requestId: 'caller-generated-unique-id',
  label: 'Move node',
  operations: [{ kind: 'node.patchGeometry', id: nodes[0].id, patch: { x: 100 } }],
});
```

上例假设至少有一个节点；实际调用必须检查查询结果。

- 读取错误：`DocumentServiceError` 携带 code。
- 操作结果：`applied / noop / rejected / conflict`、revision、requestId、actor、affectedIds、可选 code/message。
- 支持字段：已有 x/y、正数 width/height、保持点数的 points。数字必须有限且绝对值不超过 1e9。
- 不支持字段：id/type/parent/资产 locator/任意业务属性；不接收 JavaScript reducer。
- 分页 1..500；事务/选区最多 1000；每个点类节点最多 4096 points；超限拒绝，不静默截断后提交。
- 复杂 group 的子孙变换尚未定义，显式拒绝；locked 节点拒绝。随机整板排列超过 1000 节点时要求缩小选区。这个限制是本批公开的功能边界，不是任意规模事务已实现。
- requestId 去重限当前 provider/session 最近 256 项，重复 payload 返回原结果，不重复写历史；同 ID 不同 payload 拒绝。缓存淘汰后依靠严格 revision 防止旧请求重复覆盖，不提供跨重启 durable exactly-once 保证。
- 本 API 是同步 renderer 内调用；没有假设跨进程能直接传 AbortSignal，也没有新增 IPC。
- document 订阅仅表示 session/active board/node revision 变化，不是独立 selection 或 viewport 事件接口。

## 6. 未测、风险与下一批

- 未测 Windows Electron 真机 Palette 点击、真实大项目长期压力、实际文件写入与 reopen、复杂群组排列体验。
- 状态从 React 内部 state 改为 external-store 订阅可能影响调度/性能；当前完整保护测试与真实 hook 夹具通过，但没有本轮真机 FPS 或峰值内存结论。
- immutable 更新是 revision 的前提；绕过 SDK 的可信 legacy 代码若直接原地修改 Element，不会自动被发现。本批不声称消灭所有裸引用。
- 服务目录当前仅核心 provider，不能宣称第三方替换已完成；V1 scope 和此 SDK 都不是恶意代码沙箱。
- 完整 document/operations 的 create/delete/reparent、更多节点属性、复杂 group、持久化审计、权限/跨进程桥、外部 provider 仍未实现。request label 是当前请求语义，不新增持久历史 schema。
- 下一批优先完成 legacy 服务稳定代理和跨板闭包回归，扩展文档操作时逐项定义约束；不要越过 V2 收尾就另起一套导入队列。V3 继续复用既有 jobs/import 所有权，V4 再做动态节点 schema。
