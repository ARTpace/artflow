# Artflow 设置系统升级开发文档

> 交接文档：交给其他模型/开发者照做。写作日期 2026-09-23，基于当时主干代码。
> 目标：对标 Blender 偏好设置——**交互范式升级**（搜索、拖拽数值、行级重置、收起记忆）+ **参数面扩充**（画布/生成/外观/开发者工具）+ **架构还债**（settings store 统一，终结三处接线）。

> 分三个里程碑：M1 地基（store + 行 schema + 新行原语）→ M2 交互与参数填充 → M3 开发者工具 + 预设。
> 每期独立可交付、独立可验证。**严格按 M1 → M2 → M3 顺序，不要并行开期。**

## 0. 硬约束红线（先读，违反任何一条即返工）

以下语义是历史迭代中用血泪换来的，**不可破坏**：

1. **`--ui-bg-color` 写入裁决**：`hooks/useSettings.ts` 中的 `uiThemeTouchedRef` 门禁必须保留——启动时**绝不**写 `--ui-bg-color`（基线归皮肤引擎 `DEFAULT_SKIN.chrome.panelBg` 管），仅当用户在设置页主动修改 UI 主题时才写回。新 store 接管 uiTheme 时必须原样迁移这个 ref 语义。
2. **首帧 provide 时序**：`components/CanvasSettings.tsx` 的 bridge provide 发生在 render 期间（`bridgeProvidedRef` 模式），**不是** useEffect——StrictMode 双挂下 useEffect 时序会炸（历史教训："service already provided" / 白屏）。新的 preferences store 如果走 kernel.provide，同样必须在首帧 render 期完成，或用模块级单例（推荐，见 §3.1）。
3. **useEffect 清理函数**：任何在 useEffect 块体里 subscribe/provide 的代码，必须 `return () => disposers.forEach(d => d())`。StrictMode 双挂缺清理 = 二次 provide 抛错白屏（R39 教训）。
4. **同文件并行编辑禁止**：多个 Edit 并行改同一文件会互相覆盖落盘（R42 复发过）。同一文件的多次修改必须串行。
5. **manifest 白名单**：新增/修改插件 manifest 时，`category` ∈ {format, canvas, ui, ai, skin, workspace, other}，`capabilities` ∈ {format.handler, canvas.card, ui.panel, ui.settings, ui.menu, ui.skin, command, ai.provider, asset.source, node.action, exporter}，必填 `manifestVersion: 1`。设置类插件用 `"category": "ui"` + `"capabilities": ["ui.settings"]`（参考 `builtin/core-settings/manifest.json`）。违规会被隔离机制拒收（进 rejected[]，不白屏但功能不加载）。
6. **快捷键分区既有语义**：`HotkeysSection` 的冲突徽标（`buildShortcutRegistry` / `findShortcutConflicts` / `bindingIdentity`，来自 `plugins/shortcut-arbitration.ts`）是已验证的裁决链 UI，**不得改动其行为**；新分区只能复用不能重写。
7. **图标遮蔽保护**：`plugins/icon-registry.ts` 的 registerIcons 拒绝遮蔽 `BUILTIN_ICONS` 规范键的规则不得触碰。
8. **验证基线**：每期收尾必须全绿——`npx tsc --noEmit` 零新错（Model3D 存量错可忽略）、`npm run check:foundations` ok、`npm run build` 成功、无头浏览器 `bootErrors === 0`。

### 1.3 关键机制

- **bridge 数据流**：App → useSettings → CanvasSettings props → `bridgeRef.current.general = {...}`（render 期原地突变）→ 插件分区 `kernel.use(SETTINGS_UI_BRIDGE_SERVICE)` 读取。**痛点：每加一个参数要改 useSettings + CanvasSettings props + settings-bridge 接口 + createSettingsUiBridge 默认值，四处接线。**
- **分区注册**：`ctx.contributions.register<SettingsSectionContribution>('settings_sections', { id: 'builtin.xxx.yyy', pluginId, priority, value: { label, component, navGroup } })`，返回 disposer。宿主 `listSettingsSectionContributions(kernel)` 拉取渲染。navGroup：`'core'`（core-settings 四分区）| `'extensions'`（其余）。
- **canvas-view-state 服务**（view-tools 用）：`state.isGridVisible()/toggleGrid()/isGridSnap()/toggleGridSnap()/gridSize()/adjustGridSize(±n)/isDesaturate()/toggleDesaturate()/isDimUnselected()/toggleDimUnselected()`。分区组件内用 `React.useReducer(count => count + 1, 0)` 强刷（该服务无 subscribe，可顺带补）。

## 3. M1 —— 架构地基：preferences store + 行 schema + 新原语

### 3.1 preferences store（新建 `plugins/preferences-store.ts`）

**模块级单例可观察 store**，不走 kernel.provide（避免首帧时序问题，且设置消费方不一定有 kernel 引用）。

```ts
// API 草案（签名即契约，实现者不得改语义）
export type PrefValue = boolean | number | string | { [k: string]: unknown };

export interface PreferencesStore {
  get<T extends PrefValue>(key: string, fallback: T): T;
  set<T extends PrefValue>(key: string, value: T): void;      // 即时落盘 + 通知
  subscribe(key: string | null, fn: () => void): () => void;  // null = 全键；返回 disposer
  exportAll(): string;                                        // M3 预设用：JSON 字符串
  importAll(json: string, mode: 'merge' | 'replace'): void;   // M3 预设用
}

export const preferencesStore: PreferencesStore;                        // 单例
export function usePref<T extends PrefValue>(key: string, fallback: T): [T, (v: T) => void];  // React 绑定
```

实现要求：

- **双存储后端**：
  - 新参数统一存 `localStorage['bp-settings.v1']`（一个 JSON 对象，key 扁平命名如 `canvas.wheelZoomFactor`）。
  - **旧参数保持旧 key 不迁移**（`language`、`geminiApiKey`、`wheelAction`、`generateHotkey`、`presentationHotkeys`、`userEffects`）——store 支持 per-key 的 legacy adapter：`registerLegacyKey(prefKey, localStorageKey, parse?, stringify?)`。读旧 key、写旧 key，行为与现状完全一致，**零迁移风险**。禁止一次性搬迁旧 key。
- **即时落盘**：set 即写（同步 try/catch），失败 console.error 不抛出。
- **usePref 实现**：内部用 `useSyncExternalStore`（React 18）订阅单键变更，杜绝漏订阅。
- **canvas-view-state 整合**（可选但推荐）：给该服务补 subscribe（或让其内部改用 preferencesStore 存 `canvas.grid.*`），使 view-tools 分区能去掉 `force()` 强刷。若改动风险大，允许 M1 跳过、M2 再做。

**旧 state 迁移策略**：`useSettings` 改为 store 的薄适配层——每个 useState 的初始化读 store（经 legacy adapter），setter 调 `store.set` 后本地 setState（保持 App 现有重渲染路径不变）。**红线 1 的 uiThemeTouchedRef 语义原样保留**。本期只迁移**已有**参数的读写通道，不新增参数。

### 3.2 行 schema（扩展 `plugins/settings-contributions.tsx`）

```ts
export type SettingRowType = 'toggle' | 'number' | 'enum' | 'color' | 'hotkey' | 'info';

export interface SettingRowDef {
  key: string;                    // preferences store 键（如 'canvas.wheelZoomFactor'）
  label: string;                  // 中文标签（i18n 后续统一，本期直接中文 + 可选 labelEn）
  type: SettingRowType;
  default: PrefValue;             // 重置目标 + 悬停提示来源
  min?: number; max?: number; step?: number;   // number 型
  options?: { value: string; label: string }[];// enum 型
  keywords?: string[];            // M2 搜索匹配用（含英文别名）
  hint?: string;                  // 行悬停说明
  requiresRestart?: boolean;      // 显示"重启后生效"徽标（本期应避免出现此类参数）
}

// SettingsSectionContribution 扩展可选字段：
export interface SettingsSectionContribution {
  label: (language: SettingsSectionLanguage) => string;
  component: ComponentType<SettingsSectionProps>;
  navGroup?: 'core' | 'extensions';
  rows?: SettingRowDef[];         // 新增：静态行元数据（搜索/重置/标记的数据源）
  filterQuery?: string;           // 新增：宿主搜索时由宿主注入，分区组件传给 SchemaRows
}
```

**约定**：声明式参数（toggle/number/enum/color）必须同时提供 `rows` 元数据并用 `SchemaRows` 渲染；命令式复杂 UI（快捷键录制、文件上传、插件管理）不强制，允许保持手写组件，但要在 `rows` 里放 `type: 'info'` 占位行让搜索能命中该分区。

### 3.3 新 UI 原语（`plugins/settings-ui.tsx` 追加，不改既有三个）

| 原语 | API 草案 | 行为细节 |
|---|---|---|
| `DragNumber` | `{ value, onChange, min?, max?, step?, unit?, precision? }` | Blender 式：①hover 光标 `ew-resize`；②pointerdown 后横向拖动，`step × (shift ? 10 : 1)` 精调（Shift 反向语义可自定，写进 hint）；③单击进入输入框编辑，Enter/blur 提交，Esc 取消；④越界 clamp；⑤显示 `precision` 位小数；⑥拖动中 `setPointerCapture`。**键盘可达**：聚焦后 ↑↓ 改值 |
| `ToggleRow` | `{ checked, onChange, label? }` | 原生 checkbox + violet accent，替代 view-tools 里的私有 ToggleButton |
| `EnumRow` | `{ value, onChange, options }` | 原生 select，Blender 风格窄下拉（现有 Segmented 保留用于 2 选项场景） |
| `SchemaRows` | `{ defs: SettingRowDef[], filterQuery?: string }` | 按 defs 渲染行：toggle→ToggleRow、number→DragNumber、enum→EnumRow、color→现有取色块样式；**自动能力**：modified 判定（`store.get(key) !== default` 显示蓝点 + 重置按钮）、悬停 title 显示 hint + 默认值、filterQuery 按 label+keywords 过滤（空串全显） |
| `ResetButton` | `{ onClick }` | 小号「重置」按钮，仅 modified 时显示 |

`SectionBlock` 改造：`open` 状态进 `localStorage['bp-settings-collapse']`（JSON: `{ [sectionId]: boolean }`），sectionId 由 props 传入（缺省用 title，但推荐分区组件传稳定 id）。**默认全展开，保持现状观感。**

## 4. M2 —— 搜索 + 参数填充

### 4.1 宿主搜索框（CanvasSettings.tsx）

- 顶部输入框（placeholder「搜索设置…」），state `query` 注入每个 section 组件的 `filterQuery` prop。
- 过滤逻辑两层：①`rows` 元数据命中的分区保留在导航（无 rows 的分区按 label 匹配）；②SchemaRows 内部过滤行，只渲染命中行。
- 有 query 时：所有分区强制展开（覆盖 collapse 记忆）、命中关键词 `<mark>` 高亮（简单字符串包裹即可）。
- 清空 query 恢复 collapse 记忆态。

### 4.2 导航重分组

navGroup 从二组扩为视觉分组（仍用 navGroup 字段，值扩展为字符串，宿主按出现顺序渲染组标题）：建议顺序——`通用`（general/apiKey）→ `外观与主题`（appearance + 主题库入口）→ `画布与视图`（canvas + view-tools）→ `生成默认值`（新）→ `输入与快捷键`（hotkeys）→ `插件`（ui-plugin-manager）→ `系统`（新，可 M3）→ `开发者工具`（新，M3）。**宿主需兼容旧 `'core' | 'extensions'` 值**（映射到首尾组），分区各自更新自己的 navGroup。
