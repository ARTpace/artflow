# Artflow 组合控制面（Phase 0.5）

当前实现只组合 **同仓、可信的 builtin capability plugin**。它不把 renderer、camera、空间索引、存储、Worker 生命周期或 IPC 安全边界放入插件池。

## 启动顺序

1. 验证 builtin manifest；
2. 合并 `base` → `desktop` → 可选 user patch；
3. 校验重复 id、依赖、循环、已禁用的必需依赖、配置字段与类型；
4. 只激活 resolved profile 中启用的 builtin plugin；
5. 将 canvas card contribution 固化为 renderer lookup table；
6. 启动 React。render / pointermove 不重新合并 profile，也不查询 Kernel registry。

## User patch

首期 user patch 存在浏览器 `localStorage` 的键：`artflow.profile.patch.v1`。

```js
localStorage.setItem('artflow.profile.patch.v1', JSON.stringify({
  patches: [
    { id: 'builtin.cards', enabled: false }
  ]
}));
location.reload();
```

它只能：

- 以已知 plugin id 启用或禁用 capability plugin；
- 改写该 plugin 的 `configSchema` 已声明字段，且值类型必须匹配。

它不能注入代码、声明未知 plugin、修改 manifest、关闭 Runtime Core 或获取 Electron / filesystem / SQLite 权限。无效 patch 会在启动时忽略并回退到默认 profile；控制台与 `window.__bpProfile.warning` 会给出原因。

## Diagnostics 与验证

- 浏览器控制台：`window.__bpProfile.resolved`；
- 可复制 dump：`window.__bpProfile.dump()`；
- renderer 已 materialize 的卡片类型：`window.__bpRendererContributions`；
- self-check：`npm run check:foundations`；
- TypeScript + build + self-check：`npm run check`；
- renderer-local viewport-index baseline：`npm run benchmark:viewport`（同一 fixture 对比 naive 全量扫描与 grid query）。

`viewport-index` 是过渡期的内存 uniform grid：它将相机平移时的全量 viewport filter 替换为候选查询，但不会替代将来的 SQLite R-tree、Worker 查询、hit-test 索引或 operation transaction。
